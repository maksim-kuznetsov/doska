Выпуск изменений на боевой сервер Doska (VPS, один сервер, `docker compose`).
Полная процедура и контекст — `deploy/DEPLOY.md`, «Инструкция 2»; сам выпуск автоматизирован
скриптом `deploy/release.sh` на сервере.

## Параметры (переменные окружения)

Значения не хранятся в репозитории, а берутся из переменных окружения на машине, где запущен
OpenCode. Прочитай их перед работой: `echo $env:DOSKA_PROD_SSH` и `echo $env:DOSKA_PROD_DOMAIN`
(PowerShell) либо `printenv DOSKA_PROD_SSH` (bash).

- `DOSKA_PROD_SSH` — адрес для SSH: `deploy@<IP>` или алиас из `~/.ssh/config` (например
  `doska-prod`). **Обязательна.**
- `DOSKA_PROD_DOMAIN` — домен сайта без схемы, например `doska.example.com`. Нужен только для
  проверки здоровья снаружи; на сервере домен уже известен из `.env` (`DOMAIN`).

Если `DOSKA_PROD_SSH` не задана — не угадывай адрес: сообщи пользователю, как её задать, и
дождись. Если нет `ssh` или доступа к серверу — выдай готовые команды списком и попроси
выполнить их на сервере.

На сервере проект лежит в `/srv/doska`, compose-файл — `docker-compose.prod.yml`.

## Предусловие: код должен быть в origin

Прод подтягивает код из GitHub (`git pull`), а не с локальной машины. Перед обновлением
убедись, что нужные правки закоммичены и **запушены в `origin/master`**:

```bash
git status --short
git log origin/master..HEAD --oneline
```

Если есть незапушенные коммиты — сообщи об этом и предложи сначала `git push` (спроси
подтверждение). Пока код не в origin, `git pull` на сервере ничего не изменит.

## Выпуск

Одна команда на локальной машине: скрипт на сервере сам делает бэкап, `git pull`, пересборку,
проверку здоровья и откат при ошибке.

```bash
ssh "$DOSKA_PROD_SSH" 'cd /srv/doska && bash deploy/release.sh'
```

Скрипт печатает ревизии `старая → новая` и останавливается с откатом, если сборка не удалась или
API не стал здоровым. При ошибке сообщи её пользователю и не пытайся чинить сервер наугад.

**Код возврата ssh в PowerShell может быть `1`, даже когда выпуск успешен:** `ssh` и Docker пишут
прогресс сборки в stderr, и PowerShell показывает это как ошибку. Суди по выводу скрипта:
успех — это строки `API здоров.`, `Проверка https://.../api/health пройдена.` и финальная
`Готово: <старая> → <новая>.`.

**Первый запуск после добавления `release.sh`** (когда скрипта на сервере ещё нет): подтяни код
перед вызовом — дальше он делает это сам.

```bash
ssh "$DOSKA_PROD_SSH" 'cd /srv/doska && git pull --ff-only && bash deploy/release.sh'
```

Полезные параметры (передаются переменными перед `bash deploy/release.sh`):

- `SKIP_BACKUP=1` — без резервной копии (только если копия делалась отдельно).
- `HEALTH_TIMEOUT=<секунды>` — ожидание здоровья API (по умолчанию 180).

## Проверка после выпуска

```bash
curl -fsS "https://$DOSKA_PROD_DOMAIN/api/health"
```

Затем попроси пользователя открыть сайт и проверить вход и операцию, затронутую изменением.
Если видна старая версия интерфейса — обнови страницу: service worker предлагает обновление.

## Откат

`release.sh` откатывается сам при неудачной сборке или нездоровом API. Откат вручную (например,
если проблема видна уже после выпуска): верни предыдущую ревизию и пересобери.

```bash
ssh "$DOSKA_PROD_SSH" 'cd /srv/doska && git checkout <хеш-предыдущей-ревизии> && docker compose -f docker-compose.prod.yml up -d --build'
curl -fsS "https://$DOSKA_PROD_DOMAIN/api/health"
```

Тома `postgres-data`, `media-data`, `caddy-data` и сертификат сохраняются. Миграции откатом
кода **не** отменяются — схема остаётся новой; в проекте миграции аддитивны, поэтому предыдущая
версия совместима. Возврат на актуальную ветку:

```bash
ssh "$DOSKA_PROD_SSH" 'cd /srv/doska && git checkout master && git pull --ff-only && docker compose -f docker-compose.prod.yml up -d --build'
```

Восстановление данных из бэкапа — только если пострадали данные (не код):
`bash deploy/restore.sh backups/db-<дата>.sql.gz backups/media-<дата>.tgz` (перезаписывает базу и
медиа, требует подтверждения и остановки сайта).

## Важное

- Не публикуй и не передавай `.env` — секреты живут только на сервере.
- Не удаляй тома (`down -v`) — это потеря базы и медиа.
- Режим почты на проде сейчас `Email__Mode=File` (письма в `/srv/doska/outbox`, читает админ) —
  изменение деплоя его не затрагивает.
