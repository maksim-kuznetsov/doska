# pwa Specification

## Purpose

Определяет установку доски объявлений как приложения на мобильные устройства, офлайн-оболочку и порядок обновления версии, чтобы сайтом можно было пользоваться с домашнего экрана и при слабой связи.

## Requirements

### Requirement: Установка приложения

Система SHALL предоставлять возможность установки на домашний экран в браузерах, поддерживающих установку веб-приложений, при выполнении условий установки и работе по HTTPS. После установки приложение SHALL запускаться в отдельном окне без адресной строки браузера.

#### Scenario: Установка на поддерживаемом устройстве

- **WHEN** пользователь открывает сайт по HTTPS в поддерживающем браузере и условия установки выполнены
- **THEN** браузер позволяет установить приложение, а после установки оно запускается в режиме `standalone` на стартовом адресе

#### Scenario: Запуск установленного приложения

- **WHEN** пользователь запускает установленное приложение с домашнего экрана
- **THEN** приложение открывается в отдельном окне без адресной строки браузера

### Requirement: Web-манифест

Система SHALL предоставлять web-манифест с названием и коротким именем приложения, стартовым адресом внутри области действия, режимом отображения `standalone`, цветом темы и фона, языком `ru` и набором иконок.

#### Scenario: Чтение манифеста

- **WHEN** браузер запрашивает web-манифест
- **THEN** манифест содержит название, короткое имя, стартовый адрес, область действия, режим `standalone`, цвета темы и фона, язык `ru` и иконки приложения

#### Scenario: Стартовый адрес вне области действия

- **WHEN** стартовый адрес манифеста не входит в область действия приложения
- **THEN** манифест считается некорректным и установка не предлагается

### Requirement: Иконки приложения

Система SHALL предоставлять иконки приложения размеров 192×192 и 512×512 пикселей, maskable-иконку для адаптивных оболочек Android и `apple-touch-icon` для iOS. Иконки SHALL использовать брендовую палитру проекта.

#### Scenario: Иконка на домашнем экране

- **WHEN** пользователь устанавливает приложение на устройство
- **THEN** на домашнем экране отображается брендовая иконка приложения

#### Scenario: Адаптивная оболочка Android

- **WHEN** система отображает иконку в маске произвольной формы
- **THEN** значимая часть изображения остаётся видимой благодаря maskable-варианту

### Requirement: Офлайн-оболочка

Система SHALL кешировать оболочку приложения и собранные хешированные статические файлы, чтобы после хотя бы одной успешной загрузки приложение открывалось без сети. Оболочка SHALL показывать офлайн-состояние вместо данных, которые невозможно получить.

#### Scenario: Открытие приложения без сети

- **WHEN** пользователь открывает ранее загруженное приложение без подключения к сети
- **THEN** загружается оболочка приложения из кеша, а вместо данных показывается офлайн-состояние

#### Scenario: Сеть появилась снова

- **WHEN** подключение к сети восстанавливается и пользователь повторяет действие
- **THEN** приложение загружает данные с сервера без переустановки

### Requirement: Офлайн-страница

Система SHALL показывать офлайн-страницу с сообщением об отсутствии подключения и действием «Повторить», когда запрошенная страница недоступна без сети. Офлайн-страница SHALL не обращаться к API.

#### Scenario: Недоступная страница без сети

- **WHEN** пользователь открывает адрес, которого нет в кеше, без подключения к сети
- **THEN** показывается офлайн-страница с сообщением об отсутствии подключения и действием «Повторить»

#### Scenario: Повтор после восстановления сети

- **WHEN** пользователь нажимает «Повторить» после восстановления сети
- **THEN** открывается запрошенный адрес с данными с сервера

### Requirement: Ответы API не кешируются

Service worker MUST NOT кешировать ответы API и медиафайлы объявлений. Данные SHALL всегда запрашиваться у сервера, чтобы пользователь не видел устаревшие объявления, цены и статусы.

#### Scenario: Запрос данных при доступной сети

- **WHEN** приложение запрашивает объявления или медиафайл при доступной сети
- **THEN** запрос уходит на сервер, а ответ не сохраняется в кеше service worker

#### Scenario: Запрос данных без сети

- **WHEN** приложение запрашивает объявления без сети
- **THEN** показывается офлайн-состояние или ошибка, а не ранее сохранённые данные

### Requirement: Обновление версии приложения

Система SHALL обнаруживать новую версию после развёртывания и предлагать пользователю обновление. Новая версия SHALL применяться по действию пользователя с перезагрузкой страницы, а текущая версия MUST оставаться работоспособной до этого действия.

#### Scenario: Доступна новая версия

- **WHEN** пользователь открывает приложение после развёртывания новой версии
- **THEN** новая версия загружается в фоне, а интерфейс сообщает о доступном обновлении с действием «Обновить»

#### Scenario: Применение обновления

- **WHEN** пользователь выбирает «Обновить»
- **THEN** новая версия активируется и страница перезагружается с актуальной сборкой

#### Scenario: Отказ от обновления

- **WHEN** пользователь не выбирает обновление
- **THEN** приложение продолжает работать на текущей версии, а предложение обновления повторяется при следующем запуске

### Requirement: Установка из интерфейса

Система SHALL показывать действие «Установить приложение», когда браузер сообщает о доступной установке, и SHALL скрывать его после установки. Для iOS, где браузер не предоставляет такое событие, система SHALL показывать подсказку о добавлении на экран «Домой» через меню «Поделиться».

#### Scenario: Браузер поддерживает установку

- **WHEN** браузер сообщает о доступной установке
- **THEN** в интерфейсе доступно действие «Установить приложение», открывающее системное предложение установки

#### Scenario: Приложение уже установлено

- **WHEN** приложение запущено в установленном режиме
- **THEN** действие установки не показывается

#### Scenario: iOS без события установки

- **WHEN** пользователь открывает сайт в браузере iOS
- **THEN** показывается подсказка добавить приложение на экран «Домой» через меню «Поделиться»

#### Scenario: Отказ от установки

- **WHEN** пользователь закрывает предложение установки
- **THEN** предложение скрывается до конца текущего сеанса и не мешает работе с сайтом

### Requirement: Защищённый контекст

Функции установки и офлайн-работы SHALL быть доступны только в защищённом контексте: по HTTPS или на `localhost`. При открытии по HTTP на другом хосте сайт SHALL работать как обычный сайт без установки и офлайн-режима и MUST NOT показывать ошибки.

#### Scenario: HTTPS или localhost

- **WHEN** сайт открыт по HTTPS или на `localhost`
- **THEN** доступны установка приложения и офлайн-оболочка

#### Scenario: HTTP на внешнем хосте

- **WHEN** сайт открыт по HTTP на хосте, отличном от `localhost`
- **THEN** сайт работает без установки и офлайн-режима, а функции PWA не регистрируются и не показывают ошибок
