# static-assets Specification

## Purpose

Определяет, как собранные сборщиком Vite файлы интерфейса (CSS и JS) получают версию в адресе и как кешируются статика и HTML-оболочка SPA, чтобы после обновления сайта браузер не использовал устаревшие файлы.

## Requirements

### Requirement: Версия статики в адресе файла
Ссылки на CSS и JS в HTML-оболочке SPA SHALL содержать версию, вычисленную сборщиком Vite из содержимого файла (хеш в имени файла). При изменении файла адрес в HTML MUST измениться, поэтому ранее закешированная копия не будет использована.

#### Scenario: Первый деплой версии
- **WHEN** интерфейс собран (`pnpm build` в каталоге `frontend`) и HTML-оболочка SPA отдана пользователю
- **THEN** в разметке страницы адреса CSS и JS содержат версию файла

#### Scenario: Файл изменился
- **WHEN** содержимое CSS или JS изменено и интерфейс пересобран
- **THEN** HTML-оболочка SPA ссылается на новый адрес, а старый адрес остаётся доступным

#### Scenario: Файл не изменился
- **WHEN** интерфейс пересобран без изменения файлов
- **THEN** адреса CSS и JS в HTML остаются прежними

### Requirement: HTML отдаётся без кеширования
Ответы с HTML-оболочкой SPA SHALL сопровождаться заголовком `Cache-Control: no-cache`, который выставляет веб-сервер nginx, чтобы браузер ревалидировал страницу и получал ссылки на актуальные версии статики.

#### Scenario: Запрос HTML-страницы
- **WHEN** браузер запрашивает HTML-страницу у nginx
- **THEN** ответ содержит `Cache-Control: no-cache`

#### Scenario: Повторный визит после деплоя
- **WHEN** пользователь повторно открывает страницу после обновления сайта
- **THEN** браузер ревалидирует HTML и получает ссылки на новые версии CSS и JS

### Requirement: Кеширование версионированной статики
Собранные в `frontend/dist/` статические файлы SHALL отдаваться веб-сервером nginx с разрешённым браузерным кешем, а разные версии одного файла MUST иметь разные адреса, чтобы кеш одной версии не влиял на другую.

#### Scenario: Повторный запрос статики
- **WHEN** браузер в пределах срока кеша запрашивает CSS или JS по адресу с версией
- **THEN** файл берётся из кеша без обращения к серверу

#### Scenario: Смена версии
- **WHEN** файл изменился и HTML ссылается на новый адрес с версией
- **THEN** браузер загружает новый файл, не используя старую кешированную копию

### Requirement: Статика в режиме разработки без сборки
В окружении `Development` при запущенном dev-сервере Vite страницы SHALL открываться и ссылаться на доступные адреса CSS и JS, чтобы локальная разработка и тесты интерфейса не требовали отдельного шага сборки.

#### Scenario: Локальный запуск без предварительной сборки
- **WHEN** разработчик открывает страницу в окружении `Development`, не запуская сборку интерфейса
- **THEN** страница отдаётся без ошибок и подключает доступные CSS и JS

#### Scenario: Тесты без собранной статики
- **WHEN** запускаются тесты без предварительной сборки интерфейса
- **THEN** представления SPA отображаются без ошибок версионирования

### Requirement: Служебные файлы PWA не кешируются

Веб-сервер nginx SHALL отдавать web-манифест и service worker с заголовком `Cache-Control: no-cache`, чтобы браузер получал актуальные версии после развёртывания. Service worker SHALL быть доступен из корня сайта, чтобы управлять всеми страницами приложения.

#### Scenario: Запрос service worker

- **WHEN** браузер запрашивает файл service worker
- **THEN** ответ содержит `Cache-Control: no-cache`, а файл доступен из корня сайта

#### Scenario: Запрос web-манифеста

- **WHEN** браузер запрашивает web-манифест
- **THEN** ответ содержит `Cache-Control: no-cache` и тип содержимого web-манифеста

#### Scenario: Развёртывание новой версии

- **WHEN** после развёртывания браузер повторно запрашивает service worker
- **THEN** он получает новую версию файла, а не закешированную копию
