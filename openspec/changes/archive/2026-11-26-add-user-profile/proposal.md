# Proposal

## Why

При подаче объявления контакты вводятся вручную каждый раз, а в аккаунте нет страницы, где их можно сохранить один раз. Нужна страница пользователя с сохранёнными контактами, которые автоматически подставляются в форму объявления.

## What Changes

- У пользователя появляются сохраняемые данные профиля: отображаемое имя и контакты — одно свободное текстовое поле, как `Ad.Contacts`.
- Новая страница «Профиль»: редактирование отображаемого имени и контактов, а также смена пароля с проверкой текущего.
- Эндпоинты профиля для текущего пользователя: чтение и сохранение профиля, смена пароля.
- Форма подачи нового объявления предзаполняет поле «Контакты» отображаемым именем и контактами профиля в формате «имя контакты»; значение можно изменить для конкретного объявления.
- Сведения текущего пользователя (`GET /api/auth/me`) дополняются отображаемым именем и контактами для подстановки в интерфейсе.
- **BREAKING**: нет.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `user-accounts`: добавляются требования к профилю пользователя (отображаемое имя и контакты, смена пароля) и к сведениям о текущем пользователе.
- `classified-ads`: требование «Подача объявления» дополняется предзаполнением контактов из профиля.

## Impact

- Бэкенд: `Doska.Domain` (`User`), `Doska.Application` (сервис профиля, `AuthService`/`AuthenticatedUser`), `Doska.Api` (контракты, контроллер профиля, ответ `me`), `Doska.Infrastructure` (конфигурация `User`, миграция EF Core) и тесты `tests/Doska.Tests`.
- Интерфейс: новая страница профиля, маршрут и пункт меню пользователя, клиент API, предзаполнение в `AdFormView`, тесты.
- Схема БД: новые столбцы в таблице `users`, миграция EF Core.

## Вне рамок

- Структурированные контакты (телефон, мессенджеры отдельными полями) — контакты хранятся одной строкой.
- Загрузка аватара и прочие поля профиля.
- Синхронизация правок контактов из формы объявления обратно в профиль: подстановка односторонняя, поле остаётся редактируемым.
