# Spec Delta

## ADDED Requirements

### Requirement: Профиль пользователя с контактами и отображаемым именем
Система SHALL позволять вошедшему пользователю сохранять отображаемое имя и контакты, где контакты — одно свободное текстовое поле длиной не более 500 символов, и SHALL возвращать эти данные при чтении профиля.

#### Scenario: Сохранение профиля
- **WHEN** вошедший пользователь указывает отображаемое имя и контакты и сохраняет профиль
- **THEN** система сохраняет значения и подтверждает успех

#### Scenario: Пустые поля допустимы
- **WHEN** вошедший пользователь сохраняет профиль без отображаемого имени или без контактов
- **THEN** система принимает запрос и сохраняет профиль с пустыми значениями

#### Scenario: Контакты длиннее предела
- **WHEN** пользователь сохраняет контакты длиннее 500 символов
- **THEN** система отклоняет запрос с кодом 400 и сообщает о допустимой длине

#### Scenario: Сохранение без входа
- **WHEN** запрос на сохранение профиля приходит без действующей сессии
- **THEN** система отвечает кодом 401 и не изменяет данные

#### Scenario: Чтение своего профиля
- **WHEN** вошедший пользователь запрашивает профиль
- **THEN** система возвращает его отображаемое имя и контакты, не раскрывая данные других пользователей

### Requirement: Смена пароля из профиля
Система SHALL позволять вошедшему пользователю сменить пароль, требовать указания текущего пароля и SHALL применять к новому паролю те же правила сложности, что и при регистрации.

#### Scenario: Успешная смена пароля
- **WHEN** пользователь указывает верный текущий пароль и новый пароль, удовлетворяющий правилам сложности
- **THEN** система меняет пароль и подтверждает успех

#### Scenario: Неверный текущий пароль
- **WHEN** пользователь указывает неверный текущий пароль
- **THEN** система отказывает и не меняет пароль

#### Scenario: Новый пароль не проходит проверку сложности
- **WHEN** новый пароль короче минимальной длины или состоит только из цифр
- **THEN** система отклоняет запрос с кодом 400 и сообщает требования к паролю

### Requirement: Сведения о текущем пользователе включают профиль
Система SHALL включать отображаемое имя и контакты в сведения о текущем пользователе, чтобы интерфейс мог подставлять их без отдельного запроса.

#### Scenario: Ответ о текущем пользователе
- **WHEN** вошедший пользователь запрашивает сведения о себе
- **THEN** ответ содержит отображаемое имя и контакты профиля вместе с email и ролью
