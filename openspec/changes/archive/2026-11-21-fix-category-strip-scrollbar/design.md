# Design

## Context

См. `proposal.md` — Why. Полоса разделов — компонент `frontend/src/components/CategoryStrip.vue`: `<nav class="category-strip">` с единственным `<ul class="category-strip__list">`, где лежат ссылки-разделы. Прокрутку задаёт `.category-strip__list` в `frontend/src/assets/css/components.css`:

```
.category-strip__list {
  display: flex; flex-wrap: nowrap; gap: var(--space-5);
  overflow-x: auto; scrollbar-width: thin;
}
```

`scrollbar-width: thin` в Windows/Chrome рисует видимую дорожку внутри шапки. Шапка `site-header` имеет фон `var(--color-surface)`, но тот же компонент переиспользуется на странице-гайде, где фон другой (`var(--color-page)`) — значит индикатор не должен быть привязан к конкретному цвету фона.

Полоса — это блок ссылок, доступных с клавиатуры: при переходе фокуса по Tab браузер сам подкручивает список к активной ссылке, поэтому скрытие системной полосы прокрутки не лишает клавиатурной доступности.

## Goals / Non-Goals

**Goals:**

- Убрать видимую системную полосу прокрутки у полосы разделов, сохранив горизонтальную прокрутку без переноса.
- Показать градиентное затухание у края только тогда, когда за ним действительно есть непросмотренные разделы, и убрать его при достижении этого края.
- Не привязывать индикатор к цвету фона, чтобы он работал и в шапке, и в гайде.

**Non-Goals:**

- Изменение состава ссылок, навигации и данных разделов.
- Кастомизация системной полосы прокрутки для других блоков сайта.
- Замена нативного скролла на JS-перетаскивание (drag-to-scroll).

## Decisions

**Решение 1: скрыть системную полосу прокрутки у `.category-strip__list`.** Оставить `overflow-x: auto`, добавить `scrollbar-width: none` и `.category-strip__list::-webkit-scrollbar { display: none }`. Прокрутка колесом, трекпадом и касанием сохраняется, дорожка исчезает.

- *Альтернатива:* оставить `scrollbar-width: thin` — это и есть дефект из обращения.
- *Альтернатива:* `overflow: hidden` + собственный JS-скролл — лишняя сложность и потеря нативного поведения.

**Решение 2: индикатор — CSS-маска на видимой области прокрутки, а не цветной оверлей.** Затухание задаётся `mask-image: linear-gradient(...)` на `.category-strip__list` с прозрачным краем; содержимое плавно уходит в прозрачность, показывая фон под ним. Маска применяется к видимому окошку контейнера (не прокручивается вместе с содержимым), поэтому край всегда затухает у границы полосы.

- *Альтернатива:* псевдоэлементы-оверлеи с градиентом из `var(--color-surface)` в прозрачное — ломается на гайде и в любом месте с другим фоном.
- *Альтернатива:* всегда включённая маска на оба края — при малом числе разделов затемняет последнюю ссылку у края, что противоречит сценарию «Полоса без переполнения».

**Решение 3: включать затухание по фактическому переполнению, отдельно для каждого края.** Компонент хранит два флага, вычисляемые из `scrollLeft`, `clientWidth`, `scrollWidth`: затухание у левого края — есть прокрутка вправо от начала, у правого — остались разделы правее. Флаги пересчитываются при событии `scroll`, при изменении ширины через `ResizeObserver` и после смены пропа `sections`. Классы `category-strip__list--fade-start` / `category-strip__list--fade-end` включают соответствующую маску (при обоих флагах — комбинированную).

- Чистая функция `computeStripFades({ scrollLeft, clientWidth, scrollWidth })` выносится в `frontend/src/components/categoryStripFades.ts` (рядом с `formErrors.ts`) и покрывается модульным тестом: jsdom не считает раскладку, поэтому порог переполнения проверяется на функции, а компонент остаётся тонкой обвязкой.
- *Альтернатива:* считать переполнение по числу ссылок или через `getBoundingClientRect` — зависит от шрифта и вёрстки, менее надёжно, чем `scrollWidth`/`clientWidth`.

**Решение 4: проверяемое поведение.** Vitest-тест стилей (`styles.spec.ts`) фиксирует `scrollbar-width: none` и правило `::-webkit-scrollbar` для списка; модульный тест проверяет флаги затухания для случаев «помещается», «переполнено у обоих краёв», «прокручено до конца». Визуальная приёмка — ручная: jsdom не вычисляет маску и переполнение.

## Risks / Trade-offs

- [Маска-градиент поддержана не во всех браузерах] → Современные Chromium, Firefox и Safari поддерживают `mask-image`/`-webkit-mask-image`; для остальных затухание просто не покажется, а прокрутка и скрытый скроллбар продолжат работать.
- [Скрытая дорожка уменьшает «заметность» прокрутки] → Затухание у края и есть подсказка о скрытых разделах; курсор по полосе по-прежнему прокручивает её колесом/трекпадом, Tab подкручивает к фокусу.
- [`ResizeObserver` в тестах jsdom отсутствует] → Логика вынесена в чистую функцию и тестируется отдельно; обвязку с наблюдателем проверяем при необходимости через заглушку, визуально — вручную.
