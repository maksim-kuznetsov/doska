# Design

## Context

See `proposal.md` — Why. Текущее состояние:

- `scripts/smoke.ps1` проходит сквозной HTTP-сценарий, но не открывает интерфейс.
- Frontend на Vite, dev-сервер на 5173, прокси `/api` на 5000.
- Демо-учётные записи создаются командой `seed`: `user@`, `moderator@`, `admin@example.com`, пароль `123789`.
- Тесты Vitest лежат рядом с кодом; Playwright-тесты не пересекаются с ними по маске.

## Goals / Non-Goals

**Goals:**

- Проверять в реальном браузере, что страницы открываются, вход работает и роли видят свои разделы.
- Запускать одной командой локально, без изменения данных.
- Не замедлять обычные `pnpm test` и production-сборку.

**Non-Goals:**

- Полный сценарий подачи и модерации в браузере.
- CI-джоба с поднятием БД и API.
- Визуальные снимки и мобильные профили.

## Decisions

### 1. Отдельный каталог `frontend/e2e`

Playwright ищет тесты в `e2e/`, а Vitest — только в `src/**/__tests__/*.spec.ts`. Каталоги не пересекаются, поэтому обычные тесты и сборка не тянут браузерные зависимости.

### 2. `webServer` с переиспользованием

Конфигурация запускает `pnpm dev` и ждёт `http://localhost:5173`, но при уже запущенном dev-сервере использует его (`reuseExistingServer`). API и БД не поднимаются: смоук предполагает локальный стенд и демо-данные, что описано в README. Это осознанно: поднимать полный стек из Playwright-конфигурации означало бы дублировать docker compose и усложнять отладку.

### 3. Только чтение

Все проверки не создают и не меняют данные: лента, вход, служебные страницы, гайд. Это исключает побочные эффекты вроде изменения доверия демо-пользователя. Сквозной сценарий с записью остаётся за HTTP-смоуком `scripts/smoke.ps1`.

### 4. CI не меняется

Браузерный смоук требует запущенного API, PostgreSQL и seed. В CI уже выполняются интеграционные тесты и HTTP-смоук; добавление Playwright потребовало бы отдельной джобы с полным стеком. Это вынесено за рамки, чтобы не удлинять pipeline без явной необходимости.

## Risks / Trade-offs

- **Смоук зависит от демо-данных** → README требует выполнить `seed`; тест падает с понятной ошибкой, если пользователей нет.
- **Playwright скачивает браузер** → установка браузера не входит в `pnpm install`; при первом запуске нужен `pnpm exec playwright install chromium`.
- **Только чтение** → не проверяет формы; это компенсируется HTTP-смоуком и интеграционными тестами.

## Migration Plan

1. Добавить зависимость и конфигурацию, установить Chromium.
2. Запустить `pnpm --dir frontend e2e` на локальном стенде.
3. Обновить README.
4. Откат — удалить каталог `e2e` и зависимость; приложение не затрагивается.
