# Design

## Context

См. `proposal.md` — Why. `tokens.css` объявляет токены оформления, а `components.css`/`layout.css` используют литералы. CSS-переменные нельзя применять в `@media`, поэтому токены `--breakpoint-*` не работают в медиа-запросах. Спецификация `design-system` требует хранить цвета, отступы и точки перехода как токены.

## Goals / Non-Goals

**Goals:**

- Значения цветов и отступов — из токенов.
- Убрать мёртвые токены и класс, scoped-стиль и ручную разметку поля.

**Non-Goals:**

- Не менять внешний вид страниц.
- Не вводить токены ради размеров, у которых нет подходящего значения.

## Decisions

- **Цвета.** Ввести в `tokens.css` семантические токены, равные текущим литералам (`components.css:598,603,618,640,652,658,1258`); фокус-ринг на `:258` заменить на существующий `--focus-ring`. Альтернатива — подставить ближайший существующий токен отклонена: изменила бы вид.
- **Размеры.** Заменять `rem`-литералы на spacing-токены только при точном совпадении значения; иначе оставить литерал.
- **Точки перехода.** Токены `--breakpoint-mobile/tablet` удалить (в `@media` неприменимы, нигде не читаются), значения оставить литералами с комментарием. Альтернатива «оставить как документацию» отклонена: вводит в заблуждение.
- **`--opacity-muted`.** Удалить как неиспользуемый; для приглушённого текста использовать существующий muted-цвет.
- **`.divider`.** Удалить из `components.css`.
- **`AdminOutboxView`.** Перенести `.outbox-content` из scoped-`<style>` в `components.css`; компонент использует класс дизайн-системы.
- **`ModerationCard`.** Заменить ручные `field`/`input`/`textarea` на компонент `TextAreaField`.

## Risks / Trade-offs

- Визуальный регресс → сверить со `frontend/src/assets/__tests__/styles.spec.ts` и вручную проверить страницы.
- `TextAreaField` может не поддерживать нужные атрибуты (например, `readonly`) → проверить и при необходимости расширить компонент, не меняя его вид.
- Новые токены должны ссылаться на текущие значения → сравнение до/после по каждому заменённому литералу.
