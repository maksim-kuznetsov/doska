# Design

## Context

Форма фильтров ленты живёт в `web/src/components/SearchFilters.vue` как `<form class="ds-filters" method="get">` с семью контролами. Её оформление в `web/src/assets/css/components.css` — только `display: flex; flex-wrap: wrap`, поэтому ряд рвётся по длине опций. Токены оформления — в `web/src/assets/css/tokens.css`, раскладка — в `web/src/assets/css/layout.css`; шапка (`web/src/layouts/AppLayout.vue`) уже содержит поиск `.ds-search` со встроенной кнопкой и подписью `aria-label="Поиск объявлений"`. Спецификация `ad-search` задаёт поведение фильтров, сортировки и пагинации и не меняется (см. proposal.md — Capabilities). Мотивация — в proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Собрать панель фильтров из трёх смысловых частей: строка поиска, лента фильтров, диапазон цены.
- Единственная форма `method="get"` с теми же именами query-параметров (`q`, `category`, `city`, `price_min`, `price_max`, `sort`), чтобы `SearchControllerTests` и сохранение фильтров в адресе страницы при пагинации остались в силе.
- Переиспользовать существующий компонент поиска `.ds-search` вместо дублирования его вида.
- Новые классы остаются в дизайн-системе и показываются в гайде (`web/src/views/DesignSystemGuide.vue`).

**Non-Goals:**
- Не трогаем `SearchController` (`src/Doska.Api/Controllers/SearchController.cs`) и логику фильтрации/сортировки.
- Не добавляем сворачивание расширенных фильтров, чипсы и сброс — вне рамок (см. proposal.md — What Changes).
- Не удаляем поиск из шапки: ленточный поиск сохраняет фильтры, шапочный их сбрасывает, это разные роли (вариант (a) из обсуждения).

## Decisions

### Сортировка выносится в строку результатов через атрибут `form`
Управление `sort` должно остаться частью единственной GET-формы, но визуально уходит из панели в строку `.ds-results-bar`. Даём форме `id="filters-form"`, а `select[name="sort"]` в строке результатов связываем через `form="filters-form"`. Тогда форма по-прежнему отправляет все поля одним запросом, без дублирования скрытых полей.
- Альтернатива: отдельная форма сортировки со скрытыми полями текущих фильтров. Отклонено — дублирует состояние и расходится при добавлении нового фильтра.
- Улучшение (прогрессивное): обработчик `change` в `SearchFilters.vue` отправляет форму при выборе сортировки; при недоступных клиентских подсказках значение всё равно уходит по кнопке «Найти».

### Переиспользование `.ds-search` внутри панели
Строка поиска в панели повторяет вид шапочного поиска (скруглённая строка, синяя рамка, кнопка внутри). Берём ту же разметку `.ds-search`, а в `components.css` снимаем ограничение ширины: `.ds-filters .ds-search { max-width: none; }`.
- Альтернатива: отдельный класс `.ds-filter-search` с копией правил. Отклонено — нарушает «единый источник оформления».

### Явная раскладка вместо `flex-wrap`
Панель переводится на явные блоки: `.ds-filters__search` (строка 1) и `.ds-filters__row` (строка 2) на CSS Grid с равными колонками для `select`-ов; блок цены занимает свою колонку. Это убирает рваный перенос и делает положение полей независимым от длины значений.
- Альтернатива: оставить `flex-wrap` и подобрать ширины. Отклонено — поведение снова поплывёт при длинных названиях категорий.

### Диапазон цены — новый компонент `.ds-price-range`
Два поля (`price_min`, `price_max`) объединяются в блок с видимой подписью «Цена, ₽», тире-разделителем и `aria-label` на каждом поле («Цена от» / «Цена до»). Новый компонент идёт в `components.css` рядом с `.ds-filters`.
- Альтернатива: оставить два независимых поля. Отклонено — не читается как диапазон (см. proposal.md — Why).

### Строка результатов — новый компонент `.ds-results-bar`
Над списком выводится строка: слева «Найдено: N», справа подпись «Сортировка» и `select[name="sort"]`. Класс идёт в `components.css`; текущий `<p class="ds-muted">Найдено: …</p>` из `SearchFilters.vue` заменяется.

### Подписи полей вместо placeholder-подсказок
Заголовок панели-подписи задаём видимым текстом (у цены и сортировки) и `aria-label` (у `q`, `category`, `city`), чтобы смысл поля не терялся при вводе.

## Risks / Trade-offs

- [Атрибут `form` вне формы не поддерживается очень старыми браузерами] → покрытие в целевых браузерах полное; при отказе сортировка просто не отправится вместе с формой, без ошибок на странице.
- [Два поиска на одной странице (шапка + панель)] → осознанный выбор варианта (a): у них разные роли; подписи `aria-label` различают их.
- [Новые классы не появятся в гайде] → в гайде обновляется пример фильтров и добавляется пример строки результатов; сценарий спеки это требует.
- [Визуальные регрессии на узкой ширине] → проверяется ручной проверкой и сценарием «Узкая ширина».

## Migration Plan

Меняются только компонент, стили и (опционально) реактивный обработчик; миграций данных нет. Порядок: `SearchFilters.vue` → `components.css` → строка результатов и обработчик `change` → пример в гайде → прогон `pnpm test` в каталоге `web` и `dotnet test`. Откат — обычный revert изменённых файлов.
