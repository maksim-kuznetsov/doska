# Design

## Context

Дерево категорий загружается в Pinia-хранилище из эндпоинта `GET /api/categories` (`CategoriesController`) и сейчас выводится постоянной полосой `.ds-category-bar` в `web/src/layouts/AppLayout.vue` (см. proposal.md — Why). Стили компонентов живут в `web/src/assets/css/components.css`, раскладка — в `web/src/assets/css/layout.css`, а поведение подключается на Composition API в компонентах (пример: логика формы регистрации в `web/src/views/RegisterView.vue`).

## Goals / Non-Goals

**Goals:**
- Один переиспользуемый компонент выпадающего меню категорий, вставляемый в шапку кнопкой-бургером рядом с брендом и доступный на всех представлениях.
- Единая логика открытия (наведение и нажатие) и закрытия (повторное нажатие, клик вне, Escape) с корректной доступностью.
- Сохранить дерево категорий в разметке после отображения шапки, чтобы существующие проверки на присутствие названий категорий продолжали проходить.

**Non-Goals:**
- Не меняем сущность категории, эндпоинт `GET /api/categories` и фильтр категорий в форме поиска (`web/src/views/FeedView.vue`).
- Не переделываем навигацию шапки (ссылки, поиск, вход/регистрация).
- Не добавляем новых зависимостей — поведение остаётся на Composition API, как логика формы регистрации (`web/src/views/RegisterView.vue`).

## Decisions

### Общий компонент вместо копии разметки
Выносим разметку меню в `web/src/components/CategoryBurger.vue`. Компонент принимает пропсы `menuId` (уникальный id панели) и `menuLabel` (текст для `aria-label`), чтобы корректно связать `aria-controls`.
- Альтернатива: отображать меню один раз в шапке и перемещать его по DOM кодом компонента. Отклонено — хрупко, ломает разметку при невыполнении клиентских скриптов и усложняет стили.

### JS управляет состоянием, CSS — оформлением
Композабл `web/src/composables/useDropdownMenu.ts` вешает обработчики на каждый `[data-ds-menu]` и переключает класс `is-open` на корне компонента и `aria-expanded` на кнопке; панель скрыта по умолчанию через CSS. Наведение (`pointerenter`/`pointerleave` на корне) открывает и закрывает меню; нажатие кнопки переключает «закреплённое» состояние, при котором `pointerleave` не закрывает (нужно для тач-устройств и клавиатуры). Escape и клик вне закрывают меню.
- Альтернатива: чистый CSS `:hover` для наведения. Отклонено — состояние расходится с `aria-expanded`, нет закрытия по клику вне и Escape.

### Стили компонента в `components.css`
Кнопка-бургер и панель меню — переиспользуемый UI-блок, поэтому правила идут в `web/src/assets/css/components.css` под префиксом `ds-` (`.ds-menu`, `.ds-menu__toggle`, `.ds-burger`, `.ds-menu__panel`, `.ds-menu__group`). Из `web/src/assets/css/layout.css` удаляются правила `.ds-category-*`; добавляется только группа бренда `.ds-brand-group`, выравнивающая бренд и бургер. Иконка бургера рисуется средствами CSS через токены (`--ds-color-text`, `--ds-space-*`, `--ds-radius-*`, `--ds-shadow-md`), без внешних иконок. Заголовок главной остаётся обычным `<h1>` без триггера.

## Risks / Trade-offs

- [Дублирование дерева категорий в разметке] → Дерево выводится один раз в шапке; критичного роста разметки нет.
- [Меню зависит от клиентских скриптов; без них категории недоступны] → Панель присутствует в DOM; при невыполнении клиентских скриптов остаётся статичный скрытый список. Допустимо для интерактивного меню; при необходимости можно добавить `:focus-within`-фолбэк.
- [Существующие тесты ищут названия категорий в разметке] → Меню выводится сразу при отображении шапки и не подгружается лениво, поэтому названия остаются в разметке.

## Migration Plan

Изменения только в компонентах, стилях и поведении; миграций данных нет. Правки вносятся одним набором (компонент → шапка → стили → поведение → гайд → тесты) и откатываются обычным revert. После правок прогоняются `pnpm test` в каталоге `web` и проверка главной вручную.
