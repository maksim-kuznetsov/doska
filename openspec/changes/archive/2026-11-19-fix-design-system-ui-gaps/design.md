# Design

## Context

См. `proposal.md` — «Why». На текущий момент:

- Публичного адреса объявления нет: `GET /api/ads/{id}` (`AdsController`) требует входа и отдаёт объявление только автору или модератору (`AdService.GetByIdAsync`). Карточки ленты (`AdCard.vue`) не кликабельны.
- Компоненты `Breadcrumbs.vue`, `ImageGallery.vue` существуют, но применяются только в гайде и форме редактирования.
- `DropdownMenu` поддерживает разделитель `.dropdown__divider` (`UserMenu` его использует, `CategoryMenu` — нет).
- Маршруты `router/index.ts` не имеют catch-all, поэтому неизвестный адрес даёт пустую страницу.

## Goals / Non-Goals

**Goals:**

- Публичный просмотр активного объявления с галереей фотографий без входа.
- Применение компонентов системы (крошки, галерея, пустое состояние) там, где они предусмотрены спецификацией.
- Единообразие двух выпадающих меню шапки.

**Non-Goals:**

- Форма подачи жалобы из интерфейса и любые изменения правил модерации/доверия.
- Изменение токенов и компонентов дизайн-системы как таковых (правки приводят код к существующей спецификации).
- Новые эндпоинты для неактивных объявлений: доступ автора и модератора к ним сохраняется через уже существующий путь.

## Decisions

**1. Один эндпоинт `GET /api/ads/{id}` с публичным доступом к активным объявлениям.**
Снимаем с метода атрибут обязательной авторизации (`AllowAnonymous`), а в `AdService.GetByIdAsync` вводим правило видимости: объявление отдаётся, если оно активно, либо запросивший — автор или модератор; иначе — «не найдено» (не раскрываем факт существования). Viewer передаётся как `Guid?` (для анонимного запроса — `null`).

- *Альтернатива:* отдельный `GET /api/ads/{id}/public`. Отклонена — дублирует правило видимости и плодит второй путь для одного ресурса.
- *Почему «не найдено», а не «запрещено»:* неактивное объявление не должно раскрываться анонимному посетителю (см. сценарий «Неактивное объявление»).

**2. Новое представление `views/AdDetailView.vue` на маршруте `/ads/:id`.**
Собирается из компонентов системы: `ImageGallery` для фотографий, `Breadcrumbs` («Главная / Раздел / Подраздел / Объявление»), заголовок, цена, описание, контакты, раздел/город/дата. Недоступное объявление показывает `EmptyState`.

**3. Карточка ленты становится ссылкой.**
`AdCard.vue` оборачивает содержимое в `RouterLink` на маршрут объявления (блочная ссылка), сохраняя семантику `<article>`. В карточке нет вложенных интерактивных элементов, поэтому обёртка безопасна; фокус виден через `:focus-visible`.

**4. Крошки применяются на вложенных страницах.**
`Breadcrumbs` добавляется в `AdDetailView`, `AdEditView` и админ-представления (категории, города, пользователи). Главная и верхнеуровневые страницы крошек не показывают.

**5. Разделители в бургер-меню категорий.**
`CategoryMenu.vue` вставляет `<hr class="dropdown__divider">` между группами разделов — как в `UserMenu.vue`. Новых классов не вводим.

**6. Один бейдж статуса пользователя в админке.**
В `AdminUsersView.vue` из двух смежных `StatusBadge` остаётся один — состояние аккаунта (активен/скрыт); факт подтверждения email уже показан текстом в строке «Текущая роль».

**7. Заглушка 404 внутри общего макета.**
В `router/index.ts` добавляется catch-all `:pathMatch(.*)*` как дочерний маршрут `DefaultLayout`, поэтому шапка и подвал сохраняются. Новое `views/NotFoundView.vue` на `EmptyState` + `ActionLink` «На главную».

**8. Заголовок ленты без дублирования бренда.**
`HomeView.vue`: `h1` меняется с названия бренда на «Объявления», подзаголовок сохраняется.

## Risks / Trade-offs

- **Публичный доступ расширяет выдачу `GET /api/ads/{id}`** → отдаём только активные объявления, неактивные — «не найдено»; контакты показываются намеренно (доска объявлений).
- **Существующие тесты эндпоинта ожидают 401 без сессии** → обновить тесты под новое правило видимости (публичный доступ к активному, «не найдено» для неактивного, автор/модератор — к любому).
- **Ссылка вокруг всей карточки усложняет доступность** → проверяем фокус с клавиатуры и порядок обхода.

## Migration Plan

Изменений схемы БД нет — миграции не требуются. Порядок развёртывания: бэкенд (расширенный доступ к `GET /api/ads/{id}`) → интерфейс (новый маршрут и представление). Откат — возврат предыдущей версии приложения.
