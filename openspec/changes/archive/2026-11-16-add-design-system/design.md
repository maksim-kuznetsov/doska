# Design

## Context

См. `proposal.md` — Why. Текущее состояние, задающее подход:

- Весь CSS приложения — один файл `web/src/assets/css/base.css` с переменными `--bg`, `--surface`, `--text`, `--muted`, `--border`, `--accent`, `--danger`, `--success`, `--radius` и набором частных классов (`.ad-card`, `.filters`, `.stacked-form`, `.status-*`, `.message-*`).
- Представления — Vue SFC в `web/src/views/`, а `web/src/App.vue` подключает единственный файл стилей. Интерфейс собирается сборщиком Vite, каталог сборки `web/dist/` отдаётся nginx.
- Требования — в `specs/design-system/spec.md`.

## Goals / Non-Goals

**Goals:**

- Один источник истины для визуальных значений: токены как CSS custom properties, без препроцессора.
- Библиотека компонентов с предсказуемыми именами классов, покрывающая то, что уже есть на страницах.
- Базовый макет на новой системе и страница-гайд как живая документация.
- Совместимость: непереведённые страницы продолжают работать за счёт базовых стилей.

**Non-Goals:**

- Полный перевод всех представлений на новые компоненты (отдельные изменения).
- Препроцессоры CSS, CSS-in-JS, Tailwind.
- Тёмная тема, RTL, кастомные темы для пользователя.
- Переход на другой фронтенд-фреймворк.
- Копирование логотипа, названия и шрифтов Avito.

## Decisions

### 1. Токены — CSS custom properties, без препроцессора

Токены описываются как custom properties в `web/src/assets/css/tokens.css`: палитра, типографика, шкала отступов, радиусы, тени, состояния, точки перелома, ширина контейнера.

**Почему:** Vite собирает CSS без препроцессора, а custom properties работают в браузере и не требуют дополнительной обработки. **Альтернативы:** Sass/PostCSS (нужна зависимость и отдельный шаг обработки), Tailwind (утилитарные классы меняют разметку компонентов и плохо ложатся на существующий CSS).

Именование: токены `--ds-*` (`--ds-color-brand`, `--ds-space-4`, `--ds-radius-lg`). Старые имена (`--accent`, `--radius`, `--bg`, …) сохраняются как алиасы, указывающие на новые токены, чтобы существующие правила не сломались.

### 2. Палитра: точные цвета Avito плюс производные оттенки

Базовые цвета берутся из фирменной палитры Avito: `#00AAFF` (основной синий), `#FF6163` (опасность/акцент), `#97CF26` (успех), `#A169F7` (дополнительный), чёрный текст, белые поверхности, светло-серый фон. Дополнительно определяются производные оттенки: hover/active для кнопок, тинты для фонов уведомлений и бейджей.

**Почему:** пользователь выбрал максимально близкий к Avito вид; при этом часть оттенков (например, фон плашек статусов) в Avito не публикуется и подбирается в тон. **Альтернатива:** генерировать оттенки в рантайме через `color-mix()` — поддержка достаточная, но явные значения проще читать и отлаживать; выберем явные оттенки.

Контраст: `#00AAFF` с белым текстом даёт ~2.6:1 и не проходит WCAG AA. Поэтому вводится токен `--ds-color-brand-strong` (тёмный синий) для ссылок и мелкого текста; основные кнопки остаются фирменного синего ради верности референсу (см. Risks).

### 3. Шрифт: системный стек, Avito Sans не поставляем

Шрифт задаётся стеком с приоритетом системных аналогов: `Inter`, `-apple-system`, `"Segoe UI"`, `Roboto`, `Arial`, sans-serif. Сам Avito Sans не включается в репозиторий.

**Почему:** Avito Sans — проприетарный шрифт, поставка его в проект спорна с точки зрения лицензии; системный стек даёт близкий вид без бинарных файлов и сетевых запросов. **Альтернатива:** self-hosted Inter как woff2 — ближе к Avito, но добавляет бинарные ассеты; токены позволяют добавить его позже одной правкой.

### 4. Организация CSS: несколько файлов, порядок подключения в макете

```
web/src/assets/css/
  tokens.css       палитра, типографика, отступы, радиусы, тени, точки перелома
  base.css         сброс, типографика по умолчанию, ссылки, контейнер
  components.css   кнопки, поля, карточки, бейджи, уведомления, пагинация, крошки, таблицы
  layout.css       шапка, поиск, категории, подвал, сетки страниц
```

`web/src/App.vue` подключает файлы по порядку (tokens → base → components → layout). `@import` не используется, чтобы не создавать водопад запросов. Порядок фиксирован.

**Почему:** четыре файла — компромисс между читаемостью и числом запросов; nginx кэширует их как файлы сборки. **Альтернатива:** один собранный файл — нужен отдельный шаг объединения; один большой файл — теряется структура.

### 5. Компоненты: префикс `ds-` и таблица замены

Компоненты получают классы с префиксом `ds-`, состояния — суффиксом (`is-*`, `ds-btn--primary`). Переиспользуемые фрагменты оформляются как Vue-компоненты дизайн-системы в `web/src/components/` (`DsButton.vue`, `DsField.vue`, `DsPagination.vue`). Существующие частные классы заменяются `ds-` компонентами.

| Старый класс | Новый компонент |
|---|---|
| `button`, `button.danger`, `button.success` | `ds-btn`, `ds-btn--danger`, `ds-btn--success` |
| `link-button` | `ds-btn--ghost` |
| `filters`, `.stacked-form` поля | `ds-field`, `ds-input`, `ds-select`, `ds-textarea` |
| `ad-card` | `ds-card` |
| `status`, `status-*` | `ds-badge`, `ds-badge--pending/active/…` |
| `message`, `message-*` | `ds-alert`, `ds-alert--success/error/info` |
| `breadcrumbs` | `ds-breadcrumbs` |
| `pagination` | `ds-pagination` |
| `empty` | `ds-empty` |
| `users-table` | `ds-table` |

**Почему:** префикс исключает конфликты имён и явно отделяет систему от разметки страниц. **Альтернатива:** переиспользовать старые имена как канонические — меньше правок в представлениях, но смешивает систему и страницы и мешает эволюции.

### 6. Базовый макет пересобирается на компонентах

`web/src/App.vue` и `web/src/layouts/AppLayout.vue` переводятся на новые классы: шапка (`ds-header`, бренд, поисковая строка `ds-search`, навигация `ds-nav`), категорийная полоса, контейнер и подвал (`ds-footer`). Разметка блоков сохраняется, меняются классы и обёртки.

**Почему:** макет используется на всех страницах — перевод даёт максимальный визуальный эффект при малом объёме правок и служит примером применения компонентов. **Альтернатива:** оставить макет как есть — тогда новый вид не виден без перевода всех страниц.

### 7. Страница-гайд: представление уровня проекта, доступное только в окружении Development

Гайд — представление `web/src/views/DesignSystemGuide.vue` по маршруту `/design-system`. В окружении Production маршрут недоступен.

**Почему:** отдельный модуль с собственными зависимостями избыточен для статической страницы; представление в проекте не требует новых зависимостей. **Альтернатива:** отдельный модуль `DesignSystem` — чище структурно, но добавляет регистрацию маршрута и модуль ради одной страницы; экран администрирования — неудобен для примеров разметки.

Гайд содержит: образцы токенов (цвета, типографика, отступы, радиусы), все компоненты во всех вариантах и состояниях, примеры разметки.

### 8. Постепенный перевод страниц на компоненты системы

Страницы, не переведённые на компоненты в рамках этого изменения, продолжают работать за счёт базовых стилей и токенов. Полный перевод представлений — отдельное последующее изменение.

**Почему:** снижает риск визуальных регрессий и позволяет внедрять систему постепенно. **Альтернатива:** перевести всё сразу — большой диф и риск сломать страницы, выходящие за объём этого изменения.

## Risks / Trade-offs

- **Мелкий белый текст на фирменном синем `#00AAFF` не проходит WCAG AA (~2.6:1)** → ссылки и мелкий текст используют `--ds-color-brand-strong`; кнопки с белым текстом делаются крупными/полужирными, а при требовании строгого AA основной фон кнопки переключается на `brand-strong` одной правкой токена.
- **Четыре CSS-файла увеличивают число запросов** → порядок подключения фиксирован, файлы кэшируются nginx как ассеты сборки; при желании позже объединяются настройкой Vite без изменения классов.
- **Частные классы на непереведённых страницах могут конфликтовать с новыми компонентами по специфичности** → порядок подключения фиксирован, а при переводе страницы её частные классы удаляются из стилей.
- **Расхождение с Avito при обновлении их фирменного стиля** → токены изолированы в `tokens.css`, обновление палитры не затрагивает компоненты.
- **Страница-гайд может утечь на production** → маршрут недоступен в окружении Production; тест проверяет недоступность.
- **Правовые риски копирования бренда Avito** → используются только цвета и общие приёмы вёрстки; логотип, название и проприетарный шрифт Avito не используются.
- **Визуальные регрессии на непереведённых страницах** → ручная проверка ключевых экранов (лента, карточка, формы, модерация, аккаунты) и сверка оформления с прежним.

## Migration Plan

1. Добавить `tokens.css`, `base.css`, `components.css`, `layout.css` в `web/src/assets/css/` и компоненты дизайн-системы в `web/src/components/`; содержимое прежнего файла стилей переводится на токены.
2. Перевести `web/src/App.vue` и `web/src/layouts/AppLayout.vue` на новые классы и порядок подключения файлов.
3. Добавить представление `web/src/views/DesignSystemGuide.vue` и маршрут `/design-system`.
4. Проверить ключевые страницы вручную и тестами: макет, гайд в окружении Development и его недоступность в Production.
5. Откат — возврат коммита стилей и представлений; поведение страниц не зависит от дизайн-системы, откат безопасен.
6. Полный перевод остальных представлений — отдельным изменением.

## Open Questions

- Нужен ли self-hosted Inter/Avito Sans вместо системного стека — решается без изменения токенов и разметки.
- Нужны ли тёмная тема и переключатель темы — можно добавить позже через дополнительные наборы токенов.
