# Proposal

## Why

В бэкенде несколько сквозных кусков кода продублированы: резолвер «абсолютный путь или относительно корня содержимого» скопирован в пяти местах, преобразование вида ошибки в HTTP-код выполняется по магическим числам вместо перечисления, а построение набора claim'ов и проверка пользователя повторяются в `AuthController` и `Program`. Дублирование повышает риск рассинхронизации при правках.

## What Changes

- Вынести общий резолвер пути (значение настройки → абсолютный путь: если путь абсолютный — как есть, иначе от корня содержимого) и заменить пять копий: `MediaMaintenanceService`, `LocalAdPhotoStorage`, `MediaController`, `FileEmailSender`, `FileEmailOutbox`.
- Заменить в `ServiceExceptionHandler` преобразование `(int)Kind switch { 0 => 400, … }` на явное сопоставление `ServiceErrorKind` → HTTP-код.
- Ввести единое построение claim'ов/принципала сессии и использовать его в `AuthController` (вход/регистрация) и `Program` (проверка сессии), устранив дублирование.
- Сохранить наблюдаемое поведение: те же HTTP-коды, тот же набор claim'ов, та же логика проверки сессии и блокировки.

## Capabilities

Изменение не меняет наблюдаемое поведение API — это чистый рефакторинг бэкенда. Спецификации не создаются и не изменяются (`skip_specs: true`); требования `platform` (формат `ProblemDetails`, аутентификация сессией, хранение медиафайлов) сохраняются как есть.

### New Capabilities

- Нет.

### Modified Capabilities

- Нет.

## Impact

- Код: `backend/src/Doska.Infrastructure` (`Media/*`, `Email/*`), `backend/src/Doska.Api` (`Infrastructure/ServiceExceptionHandler.cs`, `Controllers/AuthController.cs`, `Program.cs`), возможен новый общий модуль.
- Тесты: `backend/tests/Doska.Tests` — проверки HTTP-кодов, аутентификации и медиа остаются без изменений.
- Публичный контракт API не меняется.

## Вне рамок

- Устранение зависимости `Doska.Application` от EF Core (`IAppDbContext` с `DbSet<>`) — архитектурное решение, не входит в это изменение.
- Дублирование нормализации имён (`CityService`/`CategoryService`) и построения дерева категорий — отдельная задача.
- Дублирование сид-данных (`ReferenceDataSeeder`/`CatalogSeedData`).
- Дублирование логики загрузки справочников на клиенте.
