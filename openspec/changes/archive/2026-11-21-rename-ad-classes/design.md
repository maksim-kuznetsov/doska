# Design

## Context

См. `proposal.md` — Why. Оформление интерфейса лежит в одном файле `frontend/src/assets/css/components.css`, компоненты Vue не содержат `scoped`-стилей и используют BEM-классы оттуда (`ad-card__title`, `ad-row__media` и т. п.). Классы `ad-*` встречаются в `components.css`, в компонентах `AdCard.vue`/`AdRow.vue`, в представлениях (`HomeView`, `MyAdsView`, `AdDetailView`, `DesignSystemGuide`, админских списках) и в тестах. Имя маршрута `ad-detail` задано в `frontend/src/router/index.ts` и упоминается в тестах.

Блокировщики рекламы применяют к странице универсальные косметические фильтры из EasyList (`easylist_general_hide.txt`): общие правила `##.ad-card`, `##.ad-grid`, `##.ad-row`, `##.ad-detail` без привязки к домену. Именно эти классы несут сетка ленты, списки и страница объявления.

## Goals / Non-Goals

**Goals:**

- Убрать из разметки и стилей имена классов, которые скрывают универсальные фильтры блокировщиков.
- Сохранить внешний вид и поведение: меняются только имена, не правила оформления и не разметка.

**Non-Goals:**

- Переименование представлений (`AdFormView`, `AdEditView`, `AdDetailView`, `MyAdsView`), типов TS API (`Ad`, `AdCard`, `AdDetail`), URL (`/ads`) и JSON-полей.
- Любые изменения бэкенда, API и зависимостей.
- Переименование классов, не входящих в семейство `ad-*` (например, `.promo-banner`).

## Decisions

**Решение 1: префикс `item-*`.** Семейство `ad-*` заменяется на `item-*`: `ad-grid` → `item-grid`, `ad-list` → `item-list`, `ad-card` → `item-card`, `ad-row` → `item-row`, `ad-detail` → `item-detail` (со всеми BEM-потомками `__media`, `__body`, `__price` и т. д.). Префикс `item-` не встречается в проекте (проверено поиском `.item-`/`class="item`) и не входит в универсальные правила EasyList.

- *Альтернатива:* `listing-*` — тоже подходит и точнее по смыслу, но выбран `item-*` как более короткий и нейтральный.
- *Альтернатива:* оставить классы и добавить `:not(...)`/переопределения — не работает: блокировщик применяет `display: none !important` своим правилом, перебить его из приложения нельзя.

**Решение 2: переименовать всё семейство, включая `.ad-list`.** Точного общего правила `##.ad-list` в EasyList нет (есть только `ad-list-item`, `ad-list-desktop`), но семейство переименовывается целиком, чтобы не оставлять смешанных имён `ad-*`/`item-*` и не наткнуться на похожее правило в другом списке.

**Решение 3: переименовать только идентификаторы, привязанные к классам.** Компоненты `AdCard.vue` → `ItemCard.vue`, `AdRow.vue` → `ItemRow.vue`, имя маршрута `ad-detail` → `item-detail`, тестовые атрибуты `data-test="ad-card"` → `item-card`, `data-test="my-ad"` → `my-item`. Имена представлений и типы API остаются: блокировщик видит только HTML и CSS, поэтому имена файлов, типов и маршрутов на скрытие не влияют, а их переименование затронуло бы контракт API.

**Решение 4: правила CSS не меняются.** В `components.css` переименовываются только селекторы; свойства и структура правил сохраняются, поэтому визуального регресса быть не должно.

**Решение 5: обновить тесты стилей и компонентов.** `styles.spec.ts` проверяет наличие правил `.ad-card`/`.ad-card__media`/`.ad-card:hover` — селекторы заменяются на `.item-card`/`.item-card__media`/`.item-card:hover`. Спецификация компонента переименовывается в `ItemCard.spec.ts` вместе с импортом и описанием.

## Risks / Trade-offs

- [Пропущенное вхождение класса] → после правок поиск `ad-(card|grid|list|row|detail)` по `frontend/` (без `openspec/`) должен не находить совпадений; `pnpm test` в `frontend/` подтверждает, что тесты ссылаются на существующие селекторы.
- [BEM-потомки карточки используются вне карточки] → в `AdDetailView.vue` классы `ad-card__meta` и `ad-card__price` стоят вне `.ad-card`; они входят в список переименования, поэтому учтены явно.
- [Имя маршрута `ad-detail`] → используется в `router/index.ts` и трёх тестах; все места обновляются, иначе упадёт навигация по карточке.
- [Поведение блокировщика зависит от списка] → закрепляется спецификацией: классы блоков объявлений не начинаются с токена `ad-`, поэтому остаются видимыми в популярных списках (EasyList, AdGuard Base).

## Migration Plan

Один коммит без шагов развёртывания. Откат — revert коммита: имена классов не влияют на данные, API и хранилище.
