# Design

## Context

См. `proposal.md` — Why. Текущее состояние и ограничения, влияющие на подход:

- Шапка — `web/src/components/AppHeader.vue`; навигация собирается из ссылок и кнопки-ghost «Выйти» (POST-запрос с antiforgery-токеном и cookie-сессией).
- В дизайн-системе уже есть компонент выпадающего меню: разметка `web/src/components/CategoryBurger.vue`, стили `.ds-menu*` в `web/src/assets/css/components.css`, поведение в `web/src/composables/useDropdownMenu.ts`.
- Композабл ищет триггер через `.ds-menu__toggle` внутри `[data-ds-menu]` и управляет классом `is-open`, `aria-expanded` и `aria-controls`; закрытие — по клику вне и Escape, другие меню закрываются автоматически.
- Триггер текущего меню жёстко квадратный (`40×40`) и рассчитан на бургер.
- Тесты шапки — в `web/src/components/__tests__/AppHeader.spec.ts` («шапка содержит бургер-меню и не содержит полосы категорий», «лента показывает обычный заголовок без меню», «внутреннее представление сохраняет бургер в шапке»).

## Goals / Non-Goals

**Goals:**
- Переиспользовать существующий компонент меню и его поведение, добавив вариант триггера и разделители, без второго composable.
- Свести навигацию авторизованного пользователя к кнопке основного действия и меню пользователя.
- Сохранить разметку доступной (клавиатура, `aria-*`) и не сломать существующие тесты шапки.

**Non-Goals:**
- Не менять права и адреса модерации; не вводить новые пункты меню.
- Не делать отдельное меню для анонимного пользователя.
- Не вводить новый вариант кнопки: «Подать объявление» использует существующий primary-стиль `ds-btn`.

## Decisions

- **Вариант меню, а не новый компонент.** Добавляем модификатор `.ds-menu--user` для контейнера и `.ds-menu__toggle--text` для триггера: кнопка получает авто-ширину, горизонтальные отступы, текстовую подпись и индикатор-стрелку вместо бургера. Композабл не меняется — он уже работает с классом `.ds-menu__toggle`. Альтернатива (отдельный компонент/поведение) отклонена: дублировала бы логику открытия/закрытия и доступность.
- **Триггер — кнопка с текстом email.** `aria-haspopup`, `aria-expanded`, `aria-controls` остаются; текст обрезается многоточием через `max-width` + `text-overflow: ellipsis`, чтобы длинный email не ломал шапку.
- **Пункты и разделители.** Вводим `.ds-menu__item` (блок-ссылка/кнопка на всю ширину панели с hover) и `.ds-menu__divider` (`border-top` + вертикальные отступы). Пункты категорий продолжают использовать прежние `.ds-menu__group/__section/__children`, их оформление не меняется.
- **Порядок и разделители в меню пользователя:** «Мои объявления» → разделитель → служебные пункты модератора (если у пользователя есть права модератора) → разделитель → «Выйти». Модераторский блок отображается только при наличии прав, поэтому при его отсутствии лишние разделители не выводятся.
- **Выход остаётся POST-запросом** внутри панели меню (запрос с antiforgery-токеном, cookie-сессия ASP.NET Core), кнопка получает оформление `.ds-menu__item`. Это сохраняет текущую защиту от подделки запроса и не требует перехода на GET-ссылку.
- **Правое выравнивание панели.** Панель меню пользователя выравнивается по правому краю (`.ds-menu--user .ds-menu__panel { right: 0; left: auto; }`), чтобы не выходить за пределы экрана у правого края шапки.
- **Кнопка основного действия.** «Подать объявление» из ссылки превращается в `<RouterLink class="ds-btn" ...>` — существующий primary-вариант (брендовый синий). Отдельный `ds-btn--accent` не вводится (согласовано с пользователем).
- **Анонимный пользователь.** Ссылки «Войти» и «Регистрация» остаются в `.ds-nav` как раньше; меню пользователя не отображается (согласовано с пользователем).
- **Гайд дизайн-системы.** В `web/src/views/DesignSystemGuide.vue` добавляется пример меню с текстовым триггером и разделителями, чтобы новый вариант был виден в гайде.

## Risks / Trade-offs

- [Композабл адресует триггер по классу `.ds-menu__toggle`] → сохраняем этот класс на текстовом триггере и проверяем поведение тестами и вручную.
- [Существующие тесты шапки проверяют строки разметки] → проверки `data-ds-menu` и `categories-menu-header` сохраняются; откроем меню пользователя в тесте, чтобы убедиться, что пункты «Мои объявления»/«Выйти» теперь внутри панели.
- [Открытие по наведению у текстового триггера] → оставляем как есть для единообразия; при необходимости поведение можно ограничить одним нажатием отдельным изменением.
- [Длинный email ломает раскладку на узком экране] → обрезаем текст триггера и сохраняем адаптивную укладку шапки в колонку (`@media max-width: 768px`).
- [Выход через POST внутри меню] → запрос с antiforgery-токеном остаётся валидным внутри `<nav>`; выход не выполняется без действующего токена.

## Migration Plan

Изменение только разметки/стилей/теста, без миграций БД и деплой-шагов. Откат — возврат прежнего содержимого `web/src/components/AppHeader.vue` и стилей.
