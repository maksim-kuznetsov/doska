# Design

## Context

См. `proposal.md` — Why. Опоры:

- Опытная пагинация уже есть в поиске объявлений: `PagedResult<T>` (`Doska.Application.Common`), `PagedResultResponse<T>` (`Doska.Api.Contracts`), ограничение размера страницы (`AdSearchService.DefaultPageSize = 12`, `MaxPageSize = 50`) и компонент `Pagination.vue` (`page`, `totalPages`, `totalCount`, событие `change`).
- `UserService.GetListAsync` сейчас возвращает `IReadOnlyList<AdminUserView>` без ограничения; `AdminUsersController.List` отдаёт массив.
- Таблицы в интерфейсе ещё нет: `components.css` не содержит стилей таблиц, а требование дизайн-системы «Единый источник оформления страниц» запрещает вводить классы оформления вне дизайн-системы.

## Goals / Non-Goals

**Goals:**

- Ограничить объём ответа списка пользователей и дать постраничную навигацию в интерфейсе.
- Показать свойства пользователя таблицей со столбцами.
- Сохранить единый источник оформления: стили таблицы — часть дизайн-системы.

**Non-Goals:**

- Поиск, фильтры и сортировка по столбцам.
- Выбор размера страницы пользователем.
- Изменение страницы правки и эндпоинтов одного пользователя.

## Decisions

### Постраничная выдача повторяет контракт поиска объявлений

`GET /api/admin/users` принимает query-параметры `page` и `pageSize` и возвращает `PagedResultResponse<AdminUserResponse>` (`items`, `totalCount`, `page`, `pageSize`). Переиспользование существующих типов и компонента `Pagination` даёт единообразный контракт и не вводит новых понятий. Альтернатива — отдельная модель страницы — отклонена как дублирование.

### Ограничение размера страницы — в сервисе

`UserService.GetListAsync(page, pageSize)` нормализует вход: `page < 1 → 1`, `pageSize < 1 → DefaultPageSize`, `pageSize > MaxPageSize → MaxPageSize` (`DefaultPageSize = 20`, `MaxPageSize = 100`). Тот же приём, что в `AdSearchService`, — защита от чрезмерного запроса независимо от клиента.

### Таблица — разметка плюс стили дизайн-системы, без отдельного компонента

Таблица одна и презентационна, поэтому вводится не новый Vue-компонент, а оформление дизайн-системы: блок стилей `.data-table` в `frontend/src/assets/css/components.css` (заголовок, разделители строк, выравнивание, обёртка с горизонтальной прокруткой) и требование «Таблица данных» в дельта-спеке дизайн-системы. Так выполняется «Единый источник оформления страниц»: классы определены в дизайн-системе, представление их не изобретает. Пример таблицы добавляется в `DesignSystemGuide.vue`.

### Представление списка

`AdminUsersView` хранит `page`, `totalPages`, `totalCount` и перезагружает страницу при переключении (`load(page)`). Ответ даёт `pageSize`, по нему считается `totalPages = ceil(totalCount / pageSize)`. Столбцы: email, имя, роль, доверие, подтверждение email, статус (бейдж блокировки), контакты, действие «Редактировать». Пустая выдача — существующий `EmptyState`; обёртка таблицы даёт горизонтальную прокрутку на узкой ширине.

### Ответ эндпоинта меняется

Массив заменяется страницей (**BREAKING** для `GET /api/admin/users`). Единственный потребитель — страница `admin/users`; тесты `UserAccountApiTests`, читавшие массив, переводятся на новый формат.

## Risks / Trade-offs

- [Ломается формат ответа `GET /api/admin/users`] → других потребителей нет; интерфейс и тесты обновляются этим же изменением.
- [Номер страницы за пределами диапазона] → сервер возвращает пустую страницу; административный сценарий не удаляет записи из списка, поэтому достаточно сброса на первую страницу при ошибке загрузки.
- [На узкой ширине таблица шире экрана] → обёртка с `overflow-x: auto` сохраняет раскладку без горизонтальной прокрутки страницы.

## Migration Plan

- Схема БД и EF Core не меняются, миграций нет.
- Выпуск обычный: `dotnet test` и `pnpm test`, затем пересборка `docker compose`.
