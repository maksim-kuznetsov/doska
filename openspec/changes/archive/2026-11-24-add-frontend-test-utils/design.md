# Design

## Context

См. `proposal.md` — Why. Тесты интерфейса — Vitest + `@vue/test-utils`, окружение `jsdom`; `vite.config.ts` задаёт `environment` и `include: ['src/**/__tests__/*.spec.ts']`, отдельного setup-файла нет. Моки и фабрики дублируются по спекам.

## Goals / Non-Goals

**Goals:**

- Один набор тестовых хелперов: мок `ApiError`, монтирование с маршрутизатором, чтение файлов репозитория, фабрики PWA и фото.

**Non-Goals:**

- Не расширять охват и не менять состав проверок.
- Не трогать продуктивный код.

## Decisions

- **Расположение.** `frontend/src/__tests__/helpers/` — файлы `*.ts` (не `*.spec.ts`), поэтому шаблон `include` не подхватывает их как тесты, а относительные импорты короткие. Альтернатива `frontend/test-utils/` вне `src` отклонена: хуже изоляция tsconfig и дальше импорты.
- **`vi.mock` и хойстинг.** Хойстинг не даёт обернуть `vi.mock` в функцию-хелпер, поэтому хелпер отдаёт класс `ApiError` и фабрику модуля-заглушки, а в спеке остаётся короткий `vi.mock(path, () => ...)`; тело класса и форма модуля централизуются. Альтернатива с `__mocks__` рядом с `api/client.ts` отклонена: требует ручного включения в каждом тесте.
- **`mountWithRouter`.** Хелпер собирает memory history, таблицу маршрутов, `push` и `isReady`; спека передаёт компонент и маршруты.
- **Конфигурационные тесты.** `read()` и `repoRoot` — в общий хелпер.
- **PWA и фото.** `createInstallPromptEvent`, `photo()`, заглушка `HTMLDialogElement` — в общие фабрики.

## Risks / Trade-offs

- Импорты разной глубины → хелперы отдают значения, а путь к `api/client` передаёт спека.
- Заглушка `HTMLDialogElement` нужна не всем тестам → это фабрика, а не глобальный setup.
- Централизация моков может «позеленить» тест при регрессии → состав проверок сохраняется без изменений.
