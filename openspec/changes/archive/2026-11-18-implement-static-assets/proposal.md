# Proposal

## Why

Спецификация `static-assets` требует, чтобы собранные CSS и JS имели версию в адресе (её даёт хеш Vite), HTML-оболочка отдавалась без кеширования, а версионированная статика — с долгим кешем. Хеширование Vite уже есть, но nginx-конфигурации, которая выставляет `Cache-Control: no-cache` для HTML и долгий кеш для файлов с хешем, нет: после обновления сайта браузер может держать старую HTML-оболочку.

## What Changes

- **HTML без кеша.** В `deploy/nginx.conf` появляется правило для `index.html` с `Cache-Control: no-cache`, поэтому браузер ревалидирует страницу и получает новые адреса статики.
- **Долгий кеш статики.** Файлы каталога `/assets/` с хешем в имени отдаются с долгим `max-age` и `immutable`.
- **Проверка версий и dev-режима.** Тест проверяет, что сборка даёт хешированные имена и манифест, nginx выставляет нужные заголовки, а dev-режим подключает исходный модуль без сборки.
- Исходный код приложения не меняется.

## Capabilities

### New Capabilities

Нет. Change закрывает требования уже описанной возможности `static-assets`.

### Modified Capabilities

Нет. Требования `openspec/specs/` не меняются, поэтому change объявляет `skip_specs: true`.

## Impact

- `deploy/nginx.conf` — заголовки кеширования HTML и статики.
- `frontend/src/__tests__` — тест конфигурации кеширования и версионирования.
- Сборка Vite и код приложения не меняются.

## Вне рамок

- CDN и внешнее кеширование.
- Service worker и офлайн-режим.
- Кеширование ответов API и медиафайлов.
