# Design

## Context

См. `proposal.md` — Why. Сейчас:

- `frontend/vite.config.ts` включает `build.manifest`; имена собранных файлов содержат хеш (`dist/assets/index-<hash>.js|css`), а `index.html` ссылается на них.
- `deploy/nginx.conf` отдаёт SPA через `try_files $uri $uri/ /index.html`, проксирует `/api` и отдаёт медиа по внутреннему пути, но заголовков кеширования не задаёт.
- В разработке интерфейс обслуживает dev-сервер Vite, `index.html` подключает `/src/main.ts`.

## Goals / Non-Goals

**Goals:**

- HTML-оболочка всегда ревалидируется браузером.
- Файлы с хешем в имени кешируются надолго и не перепроверяются.
- Локальная разработка и тесты не требуют сборки.

**Non-Goals:**

- CDN, service worker, кеширование API и медиа.

## Decisions

### 1. no-cache для HTML-оболочки

`location = /index.html { add_header Cache-Control "no-cache" always; }`. Точное совпадение срабатывает и при прямом запросе, и при внутреннем перенаправлении из `try_files`, поэтому любой ответ с HTML получает `no-cache`. Браузер ревалидирует страницу и получает разметку с новыми адресами статики.

### 2. Долгий кеш для хешированных ассетов

`location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable" always; }`. Vite кладёт собранные файлы в `/assets/` и включает хеш содержимого в имя, поэтому разные версии имеют разные адреса, а одна версия может кешироваться год. `immutable` запрещает повторную валидацию в пределах срока.

### 3. Заголовок вместо `expires`

Используется только `add_header Cache-Control`, без директивы `expires`, чтобы не получить два заголовка `Cache-Control` и предсказуемо управлять значениями.

### 4. Dev-режим без сборки

Ничего не меняется: `index.html` подключает `/src/main.ts` как модуль, dev-сервер Vite компилирует на лету. Тест закрепляет, что оболочка ссылается на исходный модуль, а не на собранный файл, поэтому локальный запуск и тесты не требуют `pnpm build`.

### 5. Тесты

Тест читает `deploy/nginx.conf` и `frontend/index.html`: проверяет `no-cache` для HTML, долгий кеш и `immutable` для `/assets/`, а также подключение исходного модуля в dev-режиме. Дополнительно тест развёртывания уже проверяет манифест сборки (его создаёт `build.manifest`).

## Risks / Trade-offs

- **`immutable` на год** → если имя файла не изменится при изменении содержимого, старый кеш останется. Vite гарантирует хеш в имени, поэтому риск отсутствует.
- **no-cache на HTML увеличивает число ревалидаций** → ответ мал, а корректность важнее экономии запросов.
- **Кеш медиа не настраивается** → вне рамок; медиа можно добавить отдельным изменением.

## Migration Plan

1. Схема и код не меняются; обновляется только конфигурация nginx.
2. Перезапуск веб-сервера: `docker compose -f docker-compose.prod.yml up -d --build web`.
3. Проверка: `pnpm --dir frontend test`, `pnpm --dir frontend build`, тесты бэкенда.
4. Откат — предыдущая версия конфигурации.
