# Proposal

## Why

Раздел `admin/users` сейчас смешивает список пользователей и управление прямо в карточках: у каждой карточки свои выпадающие списки ролей и кнопки блокировки. Действия разбросаны по списку, набор изменяемых свойств ограничен ролью и блокировкой, а изменения вступают в силу сразу без подтверждения. Нужен понятный режим: список как обзор свойств и отдельная страница полного редактирования выбранного пользователя.

## What Changes

- **Список пользователей становится обзорным.** На `admin/users` остаётся список: email, отображаемое имя, роль, контакты и статусы (блокировка, доверие, подтверждение email). Вместо встроенных полей и кнопок — ссылка «Редактировать» на страницу пользователя.
- **Новая страница редактирования** `admin/users/:id`: полное редактирование свойств пользователя — роль, доверие, блокировка, подтверждение email, отображаемое имя, контакты — с сохранением одной формой.
- **Новый API чтения и записи.** `GET /api/admin/users/{id}` возвращает свойства пользователя, `PUT /api/admin/users/{id}` сохраняет полный набор изменяемых свойств. Прежний `PUT /api/admin/users/{id}/role` заменяется общим обновлением (**BREAKING** для этого эндпоинта).
- **Email только для чтения.** Администратор видит email, но не изменяет его.
- **Новое поле формы «флажок»** в дизайн-системе (`CheckboxField`) для логических свойств (блокировка, доверие, подтверждение email).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `user-accounts`: добавляется административное управление учётными записями — список с обзором свойств, страница полного редактирования и соответствующие эндпоинты. Расширяется представление пользователя для администратора (отображаемое имя, контакты).
- `design-system`: в состав полей формы добавляется флажок, а на странице-гайде появляется его пример.

## Impact

- Бэкенд: `Doska.Domain` (`User` — установка подтверждения email в обе стороны), `Doska.Application` (`UserService` — чтение одного пользователя и полное обновление, `AdminUserView`), `Doska.Api` (`AdminUsersController`, `AdminUserResponse`), тесты `UserAccountApiTests`.
- Интерфейс: `frontend/src/views/AdminUsersView.vue` (список), новый `frontend/src/views/AdminUserEditView.vue`, `frontend/src/router/index.ts`, `frontend/src/api/client.ts`, новый `frontend/src/components/CheckboxField.vue`, `frontend/src/views/DesignSystemGuide.vue`, тесты интерфейса.
- Схема БД не меняется: все свойства уже есть в таблице `users`.
- Прежний эндпоинт смены роли удаляется — других потребителей, кроме страницы `admin/users`, у него нет.

## Вне рамок

- Смена email администратором и повторная отправка подтверждения из раздела.
- Смена/сброс пароля пользователя администратором.
- Пагинация и поиск по списку пользователей (сохраняется полный список).
- Удаление пользователей и управление привязкой Google.
- Журнал аудита административных действий.
