# Spec Delta

## ADDED Requirements

### Requirement: Список пользователей для администратора

Система SHALL показывать администратору список учётных записей с их свойствами: email, отображаемое имя, контакты, роль, доверие, блокировка и подтверждение email. Каждая запись SHALL содержать ссылку на страницу редактирования этой записи. Доступ SHALL требовать роль `Admin`.

#### Scenario: Просмотр списка

- **WHEN** администратор открывает раздел пользователей
- **THEN** он видит учётные записи с их свойствами и ссылкой на редактирование у каждой

#### Scenario: Список не даёт редактировать на месте

- **WHEN** администратор просматривает список
- **THEN** изменение свойств доступно только по ссылке на страницу записи, а не прямо в списке

#### Scenario: Пустой список

- **WHEN** учётных записей нет
- **THEN** страница показывает, что пользователей нет, вместо пустого списка

#### Scenario: Доступ только администратору

- **WHEN** список запрашивает неавторизованный пользователь или не администратор
- **THEN** сервер отвечает отказом и не раскрывает данные учётных записей

### Requirement: Редактирование пользователя администратором

Система SHALL позволять администратору открыть выбранную учётную запись и изменить роль, доверие, блокировку, подтверждение email, отображаемое имя и контакты одной формой. Email SHALL отображаться только для чтения. Сохранение SHALL применять изменения и возвращать обновлённые свойства. Доступ SHALL требовать роль `Admin`.

#### Scenario: Открытие записи на редактирование

- **WHEN** администратор выбирает пользователя в списке
- **THEN** открывается форма с текущими значениями свойств пользователя, включая email только для чтения

#### Scenario: Сохранение изменённых свойств

- **WHEN** администратор меняет роль, доверие, блокировку, подтверждение email, имя или контакты и сохраняет
- **THEN** сервер сохраняет новые значения и возвращает обновлённые свойства пользователя

#### Scenario: Управление подтверждением email

- **WHEN** администратор ставит или снимает признак подтверждения email
- **THEN** сервер сохраняет выбранное состояние подтверждения

#### Scenario: Неизвестная роль

- **WHEN** администратор отправляет роль, которой нет среди доступных
- **THEN** сервер отвечает кодом 400 и не изменяет свойства пользователя

#### Scenario: Пользователь не найден

- **WHEN** администратор запрашивает или сохраняет несуществующую учётную запись
- **THEN** сервер отвечает кодом 404

#### Scenario: Изменение недоступно не администратору

- **WHEN** сохранение свойств выполняет неавторизованный пользователь или не администратор
- **THEN** сервер отвечает отказом и не изменяет данные
