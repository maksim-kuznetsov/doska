# Design

## Context

См. `proposal.md` — Why. Текущее состояние, важное для подхода:

- `ReferenceDataSeeder.SeedAsync` (`backend/src/Doska.Infrastructure/Seed/ReferenceDataSeeder.cs`) идемпотентно создаёт 3 города и 3 раздела по 2 подраздела; запускается командами `init-data` (production) и `seed` (демо).
- `City.Name` и `Category.Name` имеют глобальный уникальный индекс в БД (`AppDbContextModelSnapshot`: `HasIndex("Name").IsUnique()`), а сервис `CategoryService.NormalizeAvailableNameAsync` проверяет уникальность названия по всей таблице. Значит, два подраздела с одинаковым названием в разных разделах невозможны, и «Другой» может быть только один.
- `CatalogService.GetCitiesAsync` сортирует города по `Name`; `City` не имеет поля порядка.
- `CatalogService.GetSectionsAsync` сортирует разделы по `SortOrder`, подразделы — по `Name`; `Category.SortOrder` есть у разделов и подразделов.
- Объявление привязывается только к подразделу (`ParentId != null`), поэтому «Другой» обязан быть подразделом.

## Goals / Non-Goals

**Goals:**

- Дать отдельную идемпотентную команду, наполняющую расширенный справочник городов и категорий, не затрагивая `ReferenceDataSeeder` и уже существующие записи.
- Заложить полный, реалистичный набор городов и дерево категорий по образцу avito.ru.
- Обеспечить вариант «Другой» в списке городов и в дереве категорий.

**Non-Goals:**

- Менять схему БД, правила уникальности, API и интерфейс.
- Перезаписывать или переименовывать существующие города и категории.
- Импортировать данные с avito.ru автоматически.

## Decisions

### 1. Отдельный сидер и команда `seed-catalog`

Новый статический класс `CatalogSeedData` (только данные) и `ExtendedCatalogSeeder` (алгоритм) в `Doska.Infrastructure/Seed`. В `Program.cs` добавляется команда `seed-catalog`, работающая и в `Development`, и в `Production` (это справочные данные, а не демо-аккаунты). `ReferenceDataSeeder` не меняется.

**Почему:** пользователь выбрал отдельную команду, чтобы полный список наполнялся по желанию и не влиял на текущий `init-data`. **Альтернатива:** расширить `ReferenceDataSeeder` — отклонена: смешала бы базовый и расширенный наборы и усложнила откат.

### 2. Идемпотентность без перезаписи

Алгоритм ищет запись по названию и создаёт только отсутствующие:

- город — по `Name` в `Cities`;
- раздел — по `Name` с `ParentId == null`;
- подраздел — по `Name` в `Categories` (глобально), с привязкой к нужному разделу при создании.

Существующие записи не изменяются (в том числе `SortOrder`, названия и признак активности). Если имя занято категорией с другим родителем, запись пропускается, а конфликт попадает в результат. Сидер возвращает сводку `(CitiesAdded, SectionsAdded, SubsectionsAdded, Skipped)`; команда пишет её в журнал.

**Почему:** это повторяет философию `ReferenceDataSeeder` и безопасно для правок администратора. **Альтернатива:** upsert с обновлением порядка — отклонена как перезапись чужих изменений.

### 3. Города: админцентры субъектов + крупнейший город

Берётся официальный перечень субъектов РФ; для каждого — административный центр, а если крупнейший по населению город отличается — он тоже. Дополнительно — город «Другой». Итого 94 города (93 + «Другой»).

Крупнейшие города, отличающиеся от админцентра: Назрань (Ингушетия), Череповец (Вологодская область), Балашиха (Московская область), Гатчина (Ленинградская область), Сургут (ХМАО — Югра), Новый Уренгой (ЯНАО). У Ленинградской области административный центр — Санкт-Петербург (уже отдельный субъект), поэтому от области добавлена Гатчина.

### 4. Категории: 12 разделов, ~92 подраздела, «Разное → Другой»

Дерево повторяет структуру avito.ru на уровне «раздел → подраздел». Названия подразделов уникальны глобально (требование индекса БД), поэтому пересекающиеся по смыслу рубрики разведены по одному разделу. Последним по `SortOrder` идёт раздел «Разное» с единственным подразделом «Другой». Названия и порядок первых разделов и подразделов совпадают с базовым сидом (`Транспорт` 1, `Недвижимость` 2, `Электроника` 3, `Автомобили`, `Мотоциклы`, `Квартиры`, `Дома`, `Телефоны`, `Ноутбуки`), чтобы повторный запуск после `init-data` не создавал дубли и не сталкивал `SortOrder`.

### 5. Тесты

Новый `ExtendedCatalogSeedTests` в `tests/Doska.Tests`: прогон сидера дважды (счётчики не растут на втором запуске), наличие города «Другой» и подраздела «Другой» в разделе «Разное», у каждого из 12 разделов есть подразделы, названия категорий уникальны, присутствуют крупнейшие города (Череповец, Сургут, Назрань, Балашиха, Гатчина, Новый Уренгой), после совместного прогона с `ReferenceDataSeeder` нет дублей базовых записей.

## Risks / Trade-offs

- [Список городов и категорий — статические данные и может устареть] → данные лежат одним файлом `CatalogSeedData`, правятся без изменения алгоритма.
- [Глобальная уникальность названий категорий может конфликтовать с уже созданными администратором категориями] → сидер пропускает занятые имена и сообщает о конфликтах в сводке, не падая.
- [«Другой» в списке городов стоит в алфавитном порядке] → зафиксировано как известное ограничение; вынос в конец — отдельное изменение сортировки каталога.
- [Расширенный сид в `Production` может создать записи, которых не ждут] → команда запускается вручную, идемпотентна и не перезаписывает существующее.

## Migration Plan

1. Добавить `CatalogSeedData` и `ExtendedCatalogSeeder`.
2. Добавить команду `seed-catalog` в `Program.cs`.
3. Добавить тесты и прогнать `dotnet test`.
4. Описать команду в `README.md` и `deploy/DEPLOY.md`.
5. Проверка на локальной среде: `dotnet run --project backend/src/Doska.Api -- seed-catalog`, затем открыть ленту и фильтры.
6. Откат: команда не меняет существующие записи; при необходимости лишние города и категории деактивируются через административные экраны.
