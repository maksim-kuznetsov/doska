# Design

## Context

См. `proposal.md` — Why. Ключевые наблюдения:

- .ds-search { flex: 1 1 320px; } в `web/src/assets/css/layout.css` — база 320px. Flex-элемент не может быть меньше базы, если `flex-shrink` не даёт нужного сжатия, поэтому суммарная ширина превышает доступную.
- Мобильный блок `@media (max-width: 768px)` в том же файле должен переопределить и базу, и ограничение ширины.
- На узкой ширине приоритет — у бренда и навигации, поэтому строка поиска должна сжиматься до своего содержимого.
- `web/src/assets/css/components.css` оформляет строку поиска как компонент дизайн-системы; правки касаются только раскладки.
- `min-height` на токенах (`--ds-control-height`) сохраняет высоту строки поиска, пока она сжимается по ширине.

## Goals / Non-Goals

**Goals:**
- Убрать растяжение строки поиска по базовой оси на мобильной ширине.
- Сохранить настольное поведение: `.ds-search` занимает свободное место в шапке.
- Застраховать правку статической проверкой в `web/src/assets/__tests__/styles.spec.ts`.

**Non-Goals:**
- Не менять порядок элементов шапки и её высоту.
- Не трогать `.ds-filters` в `components.css`.
- Не менять разметку `web/src/layouts/AppLayout.vue`.

## Decisions

### `flex: 1 1 auto` вместо `flex: 1 1 320px`
`flex-basis: auto` берёт ширину содержимого, а `flex-grow: 1` позволяет строке поиска расти при свободном месте. Это сохраняет настольное поведение и убирает растяжение на узкой ширине.
- Альтернатива: `flex: 1 1 0` — строка поиска сжимается сильнее и может стать слишком узкой рядом с брендом; отклонено.
- Альтернатива: `max-width` вместо `flex-basis` — не снимает причину, а маскирует: базис 320px всё ещё определяет положение элементов.

### Мобильное переопределение
В `@media (max-width: 768px)` строка поиска получает `flex: 0 1 auto` и `max-width: none`, чтобы не расти и не зажиматься.

### Проверка через статический разбор CSS
Тесты в этом проекте статические (`web/src/assets/__tests__/styles.spec.ts` на Vitest), поэтому проверка правила выглядит так: в `layout.css` нет `flex: 1 1 320px`, зато есть `flex: 1 1 auto`, а в мобильном блоке — `flex: 0 1 auto`. Это дешёвый и стабильный тест, но он не проверяет визуальный результат: визуальную проверку закрывает ручной прогон.

## Risks / Trade-offs

- [Правка одного `flex` влияет на другой блок] → `.ds-search` используется и в панели фильтров; проверка закрывает и это.
- [Правило остаётся несогласованным с реальным поведением в браузере] → `pnpm test` в каталоге `web` проверяет только текст CSS и не подменяет визуальную проверку; ручная проверка на 480px и 768px обязательна.
- [Правка не проходит по сжатию] → проверяем ручной проверкой в браузере, при необходимости меняем базу, а не маскируем `max-width`.

## Migration Plan

Меняется один CSS-файл и один тест; порядок: правка в `layout.css` → прогон `pnpm test` в каталоге `web` → визуальная проверка шапки в браузере на 480px и 768px. Откат — обычный revert файлов.
