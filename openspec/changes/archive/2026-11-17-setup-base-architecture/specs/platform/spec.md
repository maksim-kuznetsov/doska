# Spec Delta

## ADDED Requirements

### Requirement: Локальная среда разработки
Для локальной разработки система SHALL предоставлять отдельную среду: dev-сервер интерфейса SHALL перенаправлять запросы с префиксом `/api` на бэкенд, бэкенд SHALL разрешать запросы с источника dev-сервера через CORS только в окружении `Development`, а PostgreSQL SHALL подниматься контейнером `docker compose` с постоянным томом для данных.

#### Scenario: Проксирование запроса к API
- **WHEN** dev-сервер интерфейса получает запрос к адресу с префиксом `/api`
- **THEN** запрос перенаправляется на бэкенд с сохранением пути, и код интерфейса обращается к API по относительному адресу

#### Scenario: Прямой запрос к API из браузера в разработке
- **WHEN** браузер на странице dev-сервера обращается к бэкенду напрямую, минуя прокси
- **THEN** бэкенд разрешает источник dev-сервера, если окружение — `Development`

#### Scenario: Запуск локальной базы данных
- **WHEN** разработчик поднимает локальную среду командой `docker compose up -d postgres`
- **THEN** запускается контейнер PostgreSQL с постоянным томом и проверкой работоспособности, к которому подключается бэкенд

## MODIFIED Requirements

### Requirement: Структура репозитория

Репозиторий SHALL содержать каталог `backend` с решением `Doska.sln` (проекты `src/Doska.Domain`, `src/Doska.Application`, `src/Doska.Infrastructure`, `src/Doska.Api`, тесты `tests/Doska.Tests`) и каталог `frontend` с приложением Vue. Границы проектов SHALL соответствовать возможностям `user-accounts`, `categories`, `locations`, `classified-ads`, `ad-moderation`, `ad-search`, `notifications`.

#### Scenario: Размещение нового сценария

- **WHEN** в проект добавляется новый сценарий использования
- **THEN** правило предметной области размещается в `Doska.Domain`, оркестрация — в `Doska.Application`, доступ к данным — в `Doska.Infrastructure`, эндпоинт — в `Doska.Api`

#### Scenario: Роли проектов решения

- **WHEN** правило предметной области, сценарий использования, доступ к данным или эндпоинт размещаются в решении
- **THEN** они попадают соответственно в `Doska.Domain` (сущности и правила), `Doska.Application` (сценарии), `Doska.Infrastructure` (EF Core, миграции, почта, файлы) или `Doska.Api` (контроллеры и конфигурация)

#### Scenario: Расположение решения и приложения

- **WHEN** разработчик открывает репозиторий после клонирования
- **THEN** решение `Doska.sln` находится в каталоге `backend`, а приложение Vue — в каталоге `frontend`

#### Scenario: Состав каталога web

- **WHEN** в интерфейс добавляется новый файл
- **THEN** `frontend/src/views` содержит представления (view), `frontend/src/components` — компоненты, `frontend/src/layouts` — раскладки, `frontend/src/router` — маршруты, `frontend/src/stores` — хранилища Pinia, `frontend/src/assets` — стили и изображения

#### Scenario: Зависимости проектов

- **WHEN** сборка решения выполняется с нуля
- **THEN** `Doska.Domain` не зависит от `Doska.Infrastructure` и `Doska.Api`

### Requirement: Тестирование

Тесты бэкенда SHALL выполняться командой `dotnet test` из каталога `backend` и SHALL включать проверки эндпоинтов Web API. Тесты интерфейса SHALL выполняться командой `pnpm test` в каталоге `frontend`, лежать рядом с проверяемым кодом в каталогах `__tests__` (`frontend/src/**/__tests__/*.spec.ts`) и SHALL проверять компоненты и клиентские правила. Ни один релиз MUST NOT выполняться при падающих тестах.

#### Scenario: Прогон тестов бэкенда

- **WHEN** разработчик выполняет `dotnet test` в каталоге `backend`
- **THEN** запускаются тесты проектов бэкенда и выводится итог по пройденным и упавшим тестам

#### Scenario: Прогон тестов интерфейса

- **WHEN** разработчик выполняет тесты в каталоге `frontend`
- **THEN** запускаются тесты компонентов и клиентских правил
