# Proposal

## Why

На представлении регистрации требования к паролю видны только как статичный текст, а несоответствие обнаруживается лишь после отправки формы. Посетитель узнаёт о проблеме с опозданием и вынужден заполнять форму повторно. Живая подсказка снимает лишние попытки, не меняя правил сложности и серверной проверки.

## What Changes

- Под полем пароля на представлении регистрации появляется чек-лист из трёх пунктов: минимум 8 символов, не только цифры, пароли совпадают.
- Пункты меняют состояние по мере ввода: нейтральное до начала ввода, выполнено или не выполнено после.
- Проверка на клиенте — только подсказка. Серверная проверка пароля в `Doska.Application` остаётся единственным источником истины и продолжает отклонять несоответствующие пароли.
- Когда клиентские скрипты не выполняются, форма работает как раньше: правила пароля показаны статичным текстом, ошибки приходят после отправки.
- Публичный контракт формы и требования к сложности пароля не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `user-accounts`: регистрация получает интерактивную обратную связь по трём проверяемым в браузере правилам пароля, при сохранении серверной валидации и статичных правил при недоступных скриптах.

## Impact

- `web/src/views/RegisterView.vue`: чек-лист подсказок и подключение компонента.
- `web/src/components/PasswordHints.vue`: клиентская логика состояний подсказок на Composition API с контрактом `id="password-hints"`, `[data-password-rule]` и классами `is-ok` / `is-bad`.
- `web/src/assets/css/components.css`: нейтральное, успешное и ошибочное состояния пунктов.
- `web/src/layouts/AppLayout.vue`: подключение компонента подсказок на представлении регистрации.
- `tests/Doska.Tests` (xUnit): проверка разметки подсказок и неизменности серверной валидации.
- Зависимости, сущности, API и настройки не затрагиваются.
