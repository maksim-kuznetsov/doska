# Design

## Context

Представление регистрации (`web/src/views/RegisterView.vue`) уже показывает требования к паролю статичным текстом рядом с полем, а серверная проверка в `Doska.Application` выполняется при отправке. См. `proposal.md` — Why. Подсказки оформлены отдельным компонентом `web/src/components/PasswordHints.vue`, а форма собирается из компонентов дизайн-системы.

## Goals / Non-Goals

**Goals:**

- Дать обратную связь по трём простым правилам до отправки формы.
- Сохранить серверную валидацию единственным источником истины.
- Не ломать регистрацию, когда клиентские подсказки недоступны.

**Non-Goals:**

- Дублировать на клиенте проверку распространённых паролей и сходства с email — для этого нужен серверный набор правил.
- Добавлять новые зависимости и библиотеки проверки паролей.
- Менять состав серверной проверки и требования к паролю.

## Decisions

- **Статичный текст вместо обязательного выполнения скриптов.** Чек-лист отображается представлением регистрации, компонент подсказок лишь добавляет состояния. Альтернатива — показывать подсказки только скриптом — отклонена: когда скрипты недоступны, форма потеряла бы подсказки.
- **Отдельный компонент `web/src/components/PasswordHints.vue` вместо логики в представлении.** Позволяет переиспользовать подсказки и держать представление регистрации компактным; альтернатива с кодом в `RegisterView.vue` отклонена.
- **Состояния через классы `is-ok` / `is-bad`.** Стили остаются в CSS, логика не задаёт цвета; нейтральное состояние — отсутствие классов.
- **Проверка только трёх правил, вычислимых в браузере.** Распространённость пароля и сходство с email остаются серверными; клиентская подсказка не может гарантировать приём формы, и это ожидаемо.
- **Подключение через `web/src/layouts/AppLayout.vue`.** Точка подключения компонента подсказок без изменения общего макета и навигации.

## Risks / Trade-offs

- [Клиентская подсказка расходится с серверной проверкой] → подсказка не блокирует отправку; серверные ошибки остаются видимыми, а тест фиксирует случай пароля, прошедшего подсказки и отклонённого сервером.
- [При недоступных скриптах видны только статичные правила] → поведение совпадает с текущим, регрессии нет.
- [Компонент не попадает в собранный бандл] → сборка `pnpm build` в каталоге `web` выполняется при развёртывании, а проверка отдачи файла из `web/dist/` через nginx включена в задачи.
