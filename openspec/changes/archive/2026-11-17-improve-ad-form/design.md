# Design

## Context

Мотивация — в `proposal.md`. Ограничения, которые формируют подход:

- Компонент `web/src/views/AdFormView.vue` общий для создания и редактирования (маршруты `/ads/create` и `/ads/:id/edit`); различаются обязательность фото и наличие уже загруженных снимков.
- Поля формы — DTO `AdFormRequest` с загрузкой файлов через multipart; серверная валидация, лимиты и обработка изображений работают и менять их не нужно.
- Категории — двухуровневое дерево (`Category`, `ParentId = null` — раздел), полное имя подраздела уже даёт «Раздел / Подраздел».
- Есть токены и компоненты дизайн-системы (`ds-field`, `ds-btn`, `ds-panel`, `ds-gallery`), стили лежат в `web/src/assets/css/components.css`; страница-гайд (`web/src/views/DesignSystemGuide.vue`) и её тест перечисляют компоненты.
- Ассеты собираются Vite: имя файла содержит хеш содержимого, поэтому новые модули подхватываются существующим конвейером.

## Goals / Non-Goals

**Goals:**

- Пересобрать разметку формы из компонентов дизайн-системы: секции, две колонки, зона фото, группа «цена + ₽», сводка ошибок.
- Дать каскад «Раздел → Подраздел» и превью фото с удалением до отправки, сохранив работу при недоступных клиентских скриптах.
- Не трогать серверную валидацию, сущность `Ad` и правила модерации.

**Non-Goals:**

- Удаление уже загруженных фотографий из формы редактирования (такого действия сейчас нет вообще).
- Поля-характеристики под категорию, черновики, карта города.
- Загрузка фото на отдельный эндпоинт до отправки формы.

## Decisions

### Раскладка: CSS Grid, две колонки с липким сайдбаром

Новые классы `.ds-form-layout` (`display: grid; grid-template-columns: minmax(0, 1fr) 300px; gap`) и `.ds-form-aside` (`position: sticky; top`) в `web/src/assets/css/components.css`. На ширине до мобильной точки перелома сетка становится одноколоночной, сайдбар теряет `sticky`.

Альтернатива — одна колонка с липкой нижней панелью — проще, но пользователь выбрал вариант с сайдбаром (похоже на Avito). Риск перекрытия подвала снимается `align-self: start` и сбросом `sticky` на мобильной ширине.

### Подраздел выбирается одним сгруппированным списком

Поле выбора подраздела остаётся единственным, а его список группируется по разделам через `<optgroup>`. Группировка собирается в `src/Doska.Application` из активных подразделов и их разделов, поэтому имя раздела видно прямо в списке и отдельное поле «Раздел» не нужно.

Альтернатива — двухшаговый выбор «Раздел → Подраздел» со служебным селектом и клиентской фильтрацией — отвергнута: лишнее поле в форме и лишняя логика ради того же результата.

### Аплоадер фото как прогрессивное улучшение

Серверная загрузка файлов через multipart сохраняется. Компонент `web/src/components/PhotoDropzone.vue`:

- читает `input.files`, рисует превью через `URL.createObjectURL` (ссылки освобождаются при удалении);
- ведёт счётчик «N из 5», лимит берётся из входного параметра `max` (значение `Ads:MaxPhotos` из `appsettings.json`, приходит в ответе API);
- удаляет файл до отправки: собирает новый `FileList` через `DataTransfer` и присваивает `input.files`.

Уже загруженные фото в режиме редактирования остаются серверной галереей и в клиентский набор не входят.

Альтернатива — превью через отдельный эндпоинт — отвергнута: лишняя загрузка до подтверждения.

### Сводка ошибок и фокус по ответу сервера

Сводка ошибок строится только по ошибкам валидации, полученным от сервера: компонент `web/src/components/FormErrorSummary.vue` показывает словарь ошибок из ответа `ProblemDetails` со ссылками-якорями на поля и переводит фокус на первое неверное поле. Клиентские подсказки не подменяют серверную проверку и не могут отменить показ серверной сводки; переход по ссылке-якорю и смена фокуса происходят внутри SPA без перезагрузки страницы.

### Доступность полей

В компоненте каждому полю задаются детерминированные id для подсказки и ошибки (`<field>-help`, `<field>-error`); при ошибке поле получает `aria-invalid="true"` и `aria-describedby` со ссылками на эти id. Секции — `<fieldset>` с `<legend>`.

### Счётчик символов только там, где есть предел

Счётчик включается для полей с `maxlength` (заголовок, 200 символов). У описания лимита нет, поэтому счётчика у него нет — это согласуется со спекой («поле с ограничением длины»).

## Risks / Trade-offs

- [`DataTransfer` недоступен (старые Safari) → `input.files` не пересобрать] → компонент определяет поддержку и в этом случае скрывает кнопки удаления, оставляя превью и счётчик; набор формируется повторным выбором.
- [Клиентское превью недоступно] → подразделы остаются сгруппированным списком, а файлы уходят нативным полем выбора; отправка работает как раньше.
- [Липкий сайдбар перекрывает подвал на низких экранах] → `align-self: start`, сброс `sticky` на мобильной ширине.
- [Новый модуль не попадёт в `.vite/manifest.json`] → сборка `pnpm build` в каталоге `web` обновляет манифест; в проверку добавляется загрузка страницы формы после сборки.
- [Тест гайда перечисляет классы компонентов] → примеры новых компонентов добавляются вместе с проверками, существующие проверки не ломаются.

## Migration Plan

Миграций EF Core нет. Развёртывание — обычная доставка кода: `dotnet publish` для API и `pnpm build` в каталоге `web`. Откат — возврат предыдущей версии кода; данные не меняются.
