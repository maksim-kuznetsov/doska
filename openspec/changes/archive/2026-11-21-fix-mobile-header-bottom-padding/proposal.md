# Proposal

## Why

На мобильной ширине последняя строка шапки (выбор города) упирается прямо в нижнюю границу шапки: у `.site-header__inner` в `frontend/src/assets/css/layout.css` низ задан как `0`, а отступ снизу на настольной ширине даёт только полоса разделов (`.site-header__strip`), которая на мобильной ширине скрыта. Из-за этого низ шапки выглядит «обрезанным», а содержимое страницы идёт вплотную к шапке.

## What Changes

- В мобильном блоке `@media (max-width: 768px)` файла `frontend/src/assets/css/layout.css` правило `.site-header__inner` получает нижний отступ (`var(--space-3)`), чтобы последняя строка шапки была отделена от нижней границы. Настольная ширина не меняется: там отступ по-прежнему даёт полоса разделов.
- В `frontend/src/assets/__tests__/styles.spec.ts` добавляется статическая проверка: в мобильном блоке `layout.css` у `.site-header__inner` низ не равен `0`.
- Уточняется требование «Адаптивность» в спецификации `design-system`: на мобильной ширине шапка сохраняет отступ снизу.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `design-system`: требование «Адаптивность» уточняется — на мобильной ширине шапка сохраняет отступ снизу, и её последняя строка (выбор города) не соприкасается с нижней границей.

## Вне рамок

- Состав, порядок и высота строк шапки (бренд, бургер, поиск, город, меню) — не меняются.
- Верхний отступ и боковые отступы шапки — не меняются.
- Полоса разделов в шапке на настольной ширине и меню категорий через бургер — не меняются.
- Отступы основного содержимого страницы (`.site-main`) и промо-баннера — не меняются.
- Бэкенд, API и зависимости не затрагиваются.

## Impact

- Стили: `frontend/src/assets/css/layout.css` (мобильный блок для `.site-header__inner`).
- Тесты: `frontend/src/assets/__tests__/styles.spec.ts` (Vitest, статическая проверка CSS).
- Спецификация: `openspec/specs/design-system/spec.md`.
- Бэкенд, API и зависимости не затрагиваются.
