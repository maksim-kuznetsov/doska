# Proposal

## Why

Изменения сейчас проверяются только вручную: `dotnet build`, тесты бэкенда, `pnpm test` и production-образы не запускаются автоматически, поэтому регрессия может попасть в основную ветку. Требование «ни один релиз не выполняется при падающих тестах» пока держится на дисциплине, а не на автоматической проверке.

## What Changes

- Добавляется GitHub Actions workflow, запускаемый на push в основную ветку, pull request и вручную.
- **Backend-джоба**: .NET 10, кэш NuGet, сборка решения, проверка отсутствия неприменённых изменений модели (`dotnet ef migrations has-pending-model-changes`), применение миграций к PostgreSQL-сервису на порту 5433, запуск тестов.
- **Frontend-джоба**: Node 22, pnpm, кэш, установка по lockfile, тесты Vitest, production-сборка Vite.
- **Docker-джоба**: проверка `docker-compose.prod.yml` и сборка production-образов API и веб-сервера; выполняется после зелёных бэкенда и фронтенда.
- Отменяются устаревшие запуски для той же ветки/PR.
- README получает раздел о CI и локальном воспроизведении проверок.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Требования `openspec/specs/` не меняются; change добавляет инфраструктуру проверок, поэтому объявляет `skip_specs: true`.

## Impact

- `.github/workflows/ci.yml` — новый workflow.
- `README.md` — раздел про CI.
- Код приложения, схема БД и конфигурация развёртывания не меняются.

## Вне рамок

- Публикация образов в registry и автоматический деплой.
- Матрица версий .NET/Node и тесты на Windows/macOS.
- Сканирование зависимостей и SAST.
