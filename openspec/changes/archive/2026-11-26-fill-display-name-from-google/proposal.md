# Proposal

## Why

При входе через Google сервер получает подтверждённые имя и email пользователя, но сохраняет только email. Из-за этого «Отображаемое имя» в профиле остаётся пустым, и подстановка контактов в форме объявления (имя + контакты) не работает для Google-аккаунтов.

## What Changes

- Сервер читает имя из userinfo Google (поле `name` доступно через уже запрошенный scope `profile`) и передаёт его в разрешение Google-идентичности.
- Отображаемое имя заполняется из Google-имени, **только если у аккаунта оно ещё пустое**: при первом создании аккаунта через Google, при автоматической привязке к существующему аккаунту и при явной привязке из профиля. Имя, заданное пользователем вручную, никогда не перезаписывается.
- Имя нормализуется (обрезка пробелов) и ограничивается пределом профиля (100 символов); пустое или слишком длинное Google-имя игнорируется и не мешает входу.
- Признак `google_email` не меняется; passwordless-поведение и совместимость с откатом релиза сохраняются.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `user-accounts`: вход через Google и привязка Google из профиля — добавляется заполнение «Отображаемого имени» из имени Google, когда оно пустое.

## Impact

- Бэкенд: `GoogleAuthentication` (извлечение claim `name` из userinfo), `GoogleAuthService.SignInAsync`/`LinkAsync` (параметр имени), `User` (доменный способ задать имя из внешней идентичности), `AuthenticatedUser`/`UserResponse` не меняются по составу.
- Схема БД и миграции не меняются: столбец `display_name` уже существует.
- Интерфейс и API не меняются: имя возвращается существующим полем `displayName`.
- Отклонений от `openspec/specs/platform/spec.md` нет.

## Вне рамок

- Перезапись уже заданного отображаемого имени, синхронизация имени при последующих входах, импорт других полей профиля Google.
- Имя из поля `given_name`/комбинации частей, аватар и прочие данные Google.
- Изменение контактов профиля и прочих правил Google-входа.
