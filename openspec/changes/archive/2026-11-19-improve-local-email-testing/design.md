# Design

## Context

See `proposal.md` — Why. Текущее состояние:

- `IEmailSender` реализуют `LoggingEmailSender` (в журнал) и `SmtpEmailSender` (через `System.Net.Mail`).
- `Program.cs` выбирает отправителя по наличию `Email:Host`: пусто — журнал, иначе SMTP.
- Тесты подменяют `IEmailSender` на `CapturingEmailSender` через `ApiFactory`.
- Письма отправляют: регистрация (подтверждение), сброс пароля, отклонение и скрытие объявления, напоминание о сроке.

## Goals / Non-Goals

**Goals:**

- Дать локально читать письма без реального SMTP.
- Сделать переключение на настоящий SMTP одной настройкой, когда появятся креды.
- Не ломать существующие тесты и поведение Production.

**Non-Goals:**

- Доставляемость, шифрование писем, очередь и ретраи.
- Обязательный SMTP в Production.

## Decisions

### 1. Явный режим `Email:Mode`

Добавляется настройка `Mode` со значениями `Log`, `File`, `Smtp` и `OutboxPath` (по умолчанию `media/outbox`). Для обратной совместимости: если `Mode` пуст, он выводится из `Host` (задан — `Smtp`, иначе `Log`). Явный режим понятнее, чем неявный выбор по наличию хоста, и позволяет включить файловый ящик без SMTP.

### 2. `FileEmailSender` пишет `.eml`

Письмо сохраняется как `ГГГГММДД-ЧЧММСС-<guid>-<адрес>.eml` в `OutboxPath` (относительный путь — от каталога приложения, как у медиа). Формат `.eml` с заголовками `From/To/Subject/Date` открывается почтовыми клиентами и текстовыми редакторами; тело содержит ссылку подтверждения, сброса или причину решения. Альтернатива — отдельный инбокс-сервис — избыточна для локальной проверки.

### 3. Development по умолчанию — `File`

`appsettings.Development.json` задаёт `Email:Mode=File`, поэтому после запуска письма появляются в `media/outbox/` без настройки. Каталог исключён из репозитория через `.gitignore` (`media/`).

### 4. Mailpit как локальный SMTP

В `docker-compose.yml` добавляется `axllent/mailpit` с портами 1025 (SMTP) и 8025 (веб-инбокс). Это современный поддерживаемый аналог MailHog, работает без авторизации и TLS. Разработчик поднимает его и переключает API на `Email:Mode=Smtp`, `Host=localhost`, `Port=1025`, `UseStartTls=false`. Сервис необязательный: по умолчанию письма идут в файлы.

### 5. Fail-fast при `Smtp` без хоста

Если `Mode=Smtp`, а `Host` пуст, регистрация сервисов бросает исключение с понятным текстом, и приложение не стартует. Это лучше, чем молча терять письма. `LoggingEmailSender` остаётся для случая `Mode=Log`.

### 6. Тесты

`FileEmailSender` покрывается юнит-тестом: с абсолютным `OutboxPath` и заглушкой `IHostEnvironment` письмо создаёт файл с адресом и темой. API-тесты продолжают подменять отправителя сборщиком, поэтому режим на них не влияет.

## Risks / Trade-offs

- **Файлы в `media/outbox` накапливаются** → каталог исключён из git, письма легко удалить; отдельная очистка не нужна.
- **Mailpit добавляет порты 1025/8025** → сервис необязательный, поднимается отдельно; конфликт портов виден сразу при запуске.
- **`System.Net.Mail.SmtpClient` устаревает** → для первой версии достаточно; при переходе на внешний провайдер библиотеку можно заменить, контракт `IEmailSender` не меняется.
- **`Mode=File` не проверяет реальную отправку** → это и есть цель локального режима; Production использует `Smtp`.

## Migration Plan

1. Добавить режим и файловый отправитель; Development переключается на `File` автоматически.
2. Для проверки SMTP: `docker compose up -d mailpit`, затем запуск API с `Email__Mode=Smtp`, `Email__Host=localhost`, `Email__Port=1025`, `Email__UseStartTls=false`.
3. Переключение на реальный SMTP — только переменные `Email__Host`, `Email__Port`, `Email__UserName`, `Email__Password`, `Email__From`.
4. Откат — убрать `Mode`, вернувшись к выбору по `Host`.
