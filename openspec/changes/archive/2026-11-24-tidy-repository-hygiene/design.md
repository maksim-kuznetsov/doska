# Design

## Context

См. `proposal.md` — Why. `deploy/backup.sh`, `release.sh`, `restore.sh` повторяют преамбулу (корень проекта, `COMPOSE_FILE`/`COMPOSE_DIR`, проверка `.env`, функция `compose`). CI-шаг «Check shell syntax» выполняет `bash -n deploy/*.sh`. Локальные артефакты (`/media/keys`, `/outbox`, `/.tmp`, `/.tools`) уже перечислены в `.gitignore`.

## Goals / Non-Goals

**Goals:**

- Единая преамбула скриптов развёртывания.
- Русскоязычное описание интерфейса.
- Подтверждённое игнорирование локальных артефактов.

**Non-Goals:**

- Не менять логику резервного копирования, выпуска и отката.
- Не добавлять линтер или `.editorconfig`.

## Decisions

- **`deploy/_common.sh`.** Общий файл вычисляет `ROOT_DIR` из `BASH_SOURCE`, читает `COMPOSE_FILE`/`COMPOSE_DIR` из окружения, проверяет `.env` и объявляет функцию `compose`. Подключается через `source "$(dirname "${BASH_SOURCE[0]}")/_common.sh"`. Альтернатива — единый `deploy.sh` с подкомандами отклонена: крупнее и меняет интерфейс вызова.
- **Совместимость.** Параметры окружения и `-h/--help` сохраняются; меняется только источник общей части, сообщения и коды выхода — те же.
- **CI.** Шаблон `deploy/*.sh` уже покрывает новый файл; шаг `bash -n` остаётся зелёным.
- **`frontend/README.md`.** Краткое русское описание (запуск, сборка, тесты, PWA) со ссылкой на корневой `README.md`.
- **Артефакты.** Новых правил в `.gitignore` не требуется; добавить `/outbox/` в `.dockerignore`, если его там нет.

## Risks / Trade-offs

- `source` при запуске из другого каталога → `ROOT_DIR` вычисляется из `BASH_SOURCE`, а не из текущего каталога.
- Изменение преамбулы может изменить поведение без `.env` → сохранить те же сообщения и коды выхода.
- Русский README не должен терять полезные команды шаблона → перенести команды запуска/сборки.
