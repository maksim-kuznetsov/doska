# Proposal

## Why

Спецификация `user-accounts` требует восстановления доступа по одноразовой ссылке и управления ролями администратором. Регистрация, подтверждение email, вход, подсказки к паролю, роли и блокировка уже реализованы, но сброса пароля нет, а роль пользователя меняется только вручную в базе. Из-за этого пользователь, забывший пароль, не может восстановить доступ, а администратор не может назначить модератора через интерфейс.

## What Changes

- **Сброс пароля.** `AuthService.RequestPasswordResetAsync` отправляет письмо с одноразовой ссылкой, не раскрывая, существует ли адрес; `ResetPasswordAsync` меняет пароль и делает ссылку недействительной, просроченная или использованная ссылка отклоняется.
- **Одноразовость.** Новый запрос помечает прежние неиспользованные токены сброса использованными, поэтому действующей остаётся только последняя ссылка.
- **Роли.** `UserService` даёт администратору список пользователей и смену роли; роль применяется сервером к каждому действию через политики.
- **API.** Добавляются `POST /api/auth/forgot-password`, `POST /api/auth/reset-password` и `GET /api/admin/users`, `PUT /api/admin/users/{id}/role`.
- **Интерфейс.** Появляются страницы «Забыли пароль?», «Сброс пароля» и «Пользователи» для администратора; клиент API получает методы блокировки.
- **Тесты.** API-тесты сброса (существующий и несуществующий адрес, использование, повторное использование) и смены роли (успех, запрет для модератора), тесты интерфейса.

## Capabilities

### New Capabilities

Нет. Change реализует уже описанную возможность `user-accounts`.

### Modified Capabilities

Нет. Требования `openspec/specs/` не меняются, поэтому change объявляет `skip_specs: true`.

## Impact

- `backend/src/Doska.Application/Auth/AuthService.cs` — сценарии сброса пароля.
- `backend/src/Doska.Application/Accounts/UserService.cs` — административное управление ролями.
- `backend/src/Doska.Api` — эндпоинты, контракты и регистрация служб.
- `backend/tests/Doska.Tests` — API-тесты сброса и ролей.
- `frontend/src` — страницы сброса и пользователей, клиент API, маршруты.
- Схема БД не меняется: `user_tokens` и `Purpose.PasswordReset` уже есть.

## Вне рамок

- Смена пароля из личного кабинета при известном текущем пароле.
- Двухфакторная аутентификация и вход через внешних провайдеров.
- Удаление аккаунтов пользователей.
- Управление ролями модератором (только администратор).
