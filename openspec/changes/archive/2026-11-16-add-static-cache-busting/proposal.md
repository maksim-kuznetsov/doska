# Proposal

## Why

nginx отдаёт ассеты интерфейса из `web/dist/` с кешем на 7 дней, а имена файлов CSS и JS не меняются между деплоями. После обновления кода браузер продолжает использовать старые файлы из кеша, и правки оформления или скриптов не видны до ручной очистки кеша. Сама HTML-оболочка SPA при этом не имеет явных заголовков и может кешироваться эвристически.

## What Changes

- Сборка интерфейса переходит на версионирование средствами Vite: `pnpm build` в каталоге web создаёт файлы с хешем содержимого в имени и манифест `web/dist/.vite/manifest.json`, а Vue-компоненты получают адреса ассетов по этому манифесту. Разметку менять не нужно — версия появляется в пути автоматически при изменении файла.
- nginx для HTML-оболочки SPA и всех проксируемых HTML-ответов отдаёт `Cache-Control: no-cache` (с `always`), чтобы после деплоя браузер всегда получал свежий HTML со ссылками на новые версии статики. Ассеты из `web/dist/` продолжают кешироваться с `expires 7d`.
- Изменение вносится в оба конфига nginx — `deploy/nginx.conf` и `deploy/nginx.https.conf`, потому что HTTPS-конфиг копируется поверх основного на сервере.
- Тесты: окружение Vitest переводится на работу без предварительного `pnpm build`, чтобы тесты не требовали собранных ассетов; добавляются проверки хешированных имён в манифесте и наличия заголовков в конфигах nginx.
- `deploy/release.sh` и `deploy/rollback.sh` перезагружают nginx после обновления кода: `docker compose up -d --build` не пересоздаёт контейнер при изменении только файла конфига в bind mount.
- `deploy/DEPLOY.md` дополняется проверкой после обновления версии.

## Impact

- `web/vite.config.ts` — сборка с хешем содержимого в именах файлов и манифестом.
- `deploy/nginx.conf`, `deploy/nginx.https.conf` — заголовки кеширования проксируемых HTML-ответов.
- `deploy/release.sh`, `deploy/rollback.sh` — перезагрузка nginx для применения конфига.
- `web/src/**/*.spec.ts` — поддержка тестов без предварительной сборки ассетов и новые проверки (в том числе `web/src/assets/__tests__/staticAssets.spec.ts`).
- `deploy/DEPLOY.md` — шаг проверки после деплоя.
- Сборка контейнера не меняется: `pnpm build` уже выполняется при сборке образа `web`.

## Вне рамок

- Не меняем TTL кеша ассетов (остаётся 7 дней) и не добавляем CDN.
- Не трогаем `/media/`: там UUID-имена, кеш уже безопасен.
- Не меняем `deploy/sync.ps1`, схему БД и пользовательские сценарии.
- Не настраиваем кеширование HTML на промежуточных прокси — только заголовок от nginx.
