# Design

## Context

См. `proposal.md` — Why. Сейчас:

- `Ad` хранит `PublishedAt`, `ReminderSentAt` и константу `LifetimeDays = 7`; `Renew`, `ReturnToSale` и `CompleteEdit` сбрасывают `ReminderSentAt`.
- `AdService.ArchiveExpiredAsync` архивирует активные объявления старше семи дней; вызывается фоновой службой раз в час.
- `IEmailSender` уже используется модерацией; в тестах подменяется на `CapturingEmailSender`.
- Статусы и причины в «Моих объявлениях» уже отдаются `AdService.GetMineAsync`.

## Goals / Non-Goals

**Goals:**

- Отправлять ровно одно напоминание за сутки до автоархива.
- Сохранить идемпотентность и не менять схему БД.
- Переиспользовать существующую фоновую службу и абстракцию почты.

**Non-Goals:**

- Push/SMS, отказ от писем, повторные напоминания, очередь писем.

## Decisions

### 1. Окно напоминания в `AdService.SendExpiryRemindersAsync`

Выборка: `Status == Active`, `ReminderSentAt == null`, `PublishedAt > now - 7 дней` и `PublishedAt <= now - 6 дней`. Верхняя граница означает «до автоархива осталось не более суток», нижняя — «объявление ещё не должно быть архивировано». Так объявление, которое уже пора архивировать, не получает бессмысленного письма, а служба автоархива обрабатывает его первой.

### 2. Однократность через `ReminderSentAt`

Перед отправкой поле выставляется в текущий момент и сохраняется вместе с письмом. Повторный запуск не находит объявление, потому что выборка требует `ReminderSentAt == null`. Продление и возврат в продажу сбрасывают поле, поэтому напоминание считается по новому сроку публикации. Отдельного журнала отправок не требуется.

### 3. Одна фоновая служба на два прохода

`AdArchiveBackgroundService` сначала архивирует истёкшие объявления, затем отправляет напоминания оставшимся. Это сохраняет один плановый проход и одну настройку интервала; отключение службы (`Ads:ArchiveBackgroundService=false`) по-прежнему выключает обе задачи в интеграционных тестах.

### 4. Почта через `IEmailSender`

`AdService` получает `IEmailSender` через конструктор, как `ModerationService`. Письмо содержит заголовок объявления и предложение продлить; получатель — только автор.

### 5. Тесты

Интеграционные тесты вызывают `SendExpiryRemindersAsync` через DI и проверяют `CapturingEmailSender`: письмо в окне, отсутствие письма вне окна, однократность повторного запуска и возобновление после продления. Данные помечаются префиксом и удаляются в `DisposeAsync`.

## Risks / Trade-offs

- **Письмо может быть отправлено перед архивацией в тот же час** → напоминание уходит за сутки, а архив — через сутки; окно не пересекается с архивацией.
- **Сбой отправки письма** → исключение прерывает проход, и напоминание будет повторено при следующем запуске, так как `ReminderSentAt` ещё не сохранён. Повторная отправка в худшем случае дублирует письмо — приемлемо.
- **Фоновая служба выключена в тестах** → сценарий тестируется прямым вызовом, что проверяет правило, а не расписание.

## Migration Plan

1. Схема не меняется, миграции не создаются.
2. Поведение включается вместе с существующей фоновой службой.
3. Проверка: `dotnet build`, тесты бэкенда, `pnpm --dir frontend test`, `pnpm --dir frontend build`.
4. Откат — предыдущая версия; данные совместимы.
