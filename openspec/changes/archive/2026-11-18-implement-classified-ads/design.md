# Design

## Context

See `proposal.md` — Why. Текущее состояние:

- `Ad` уже хранит `PublishedAt`, `ReminderSentAt`, `ModerationReason`, `Status`; схема `ad_photos` содержит `file_name`, `thumbnail_file_name`, `content_type`, `byte_size`, `sort_order`, `width`, `height`.
- `AdService` создаёт объявление по правилам доверия и суточного лимита, валидирует подраздел и город; `AdSearchService` показывает только активные.
- `DemoDataSeeder` и `CatalogService` работают с категориями и городами.
- `IAppDbContext`, `IEmailSender`, `TimeProvider` и cookie-аутентификация уже есть.

## Goals / Non-Goals

**Goals:**

- Закрыть требования `classified-ads` без изменения схемы.
- Хранить медиа через абстракцию, пригодную к замене на S3.
- Сохранить сервер источником правил: владение, лимиты, статусы, срок.

**Non-Goals:**

- Перестановка фото, галерея объявления, S3.
- Фоновые напоминания о сроке (уйдут в `notifications`).
- Пакетная обработка и CDN.

## Decisions

### 1. Подача — `multipart/form-data`

`POST /api/ads` принимает поля и файлы одним запросом: `[FromForm] CreateAdForm` с `List<IFormFile> Photos`. Альтернатива «создать JSON, потом догрузить фото» оставляет окно, в котором объявление существует без обязательных фотографий. Multipart сохраняет атомарность бизнес-операции и позволяет проверить 1–5 файлов до создания записи.

### 2. Хранилище медиа — абстракция + локальный том

`IAdPhotoStorage` в `Doska.Application` принимает `PhotoUpload` (поток, имя, тип, размер) и возвращает имена файла и превью, тип, размер и размеры. `LocalAdPhotoStorage` пишет в `Media:RootPath/photos/<adId>/`, генерирует имя, сохраняет оригинал и уменьшенную копию. Такой же контракт позже реализует S3-хранилище без изменения сценариев.

### 3. Уменьшение — SkiaSharp

Оригинал сохраняется в исходном формате; превью — JPEG шириной до 400 px (с сохранением пропорций, без апскейла). `SkiaSharp` (MIT) декодирует файл, поэтому одновременно проверяется целостность и формат. Альтернатива без библиотеки не даёт реального уменьшения; `ImageSharp` 4 требует лицензию, а 3.1.x имеет известные уязвимости; `System.Drawing` ограничен Windows.

### 4. Отдача медиа — внутренний редирект или поток

Контроллер медиа проверяет имя файла (защита от обхода пути) и в `Production` отвечает `X-Accel-Redirect` на внутренний путь nginx, а в `Development` отдаёт файл потоком. Это соответствует `platform`: в развёртывании файл отдаёт веб-сервер, локально приложение остаётся самодостаточным.

### 5. Жизненный цикл — методы домена

`Ad.UpdateDetails`, `MarkSold`, `ReturnToSale`, `Archive`, `Renew` проверяют допустимость перехода. Сценарии проверяют владение (403), вызывают метод, сохраняют и возвращают представление. Редактирование непроверенным автором переводит объявление в «на проверке»; доверенный сохраняет текущий статус.

### 6. Автоархив — идемпотентный фоновый сервис

`AdArchiveBackgroundService` раз в час (интервал настраивается) вызывает `AdService.ArchiveExpiredAsync`: активные объявления с `PublishedAt <= now - 7 дней` переводятся в «архив». Повторный запуск ничего не меняет, потому что условие выбирает только активные. Тот же сценарий доступен тестам напрямую. Напоминания о сроке будут добавлены в `notifications` на этом же сервисе.

### 7. Продление

`Renew` разрешён для активного и архивного объявления: `PublishedAt = now`, при архиве статус становится «активно», `ReminderSentAt` сбрасывается. Для проданного продление не предусмотрено — сначала возврат в продажу.

### 8. Интерфейс

Форма подачи использует `FormData` с файлами и показывает превью/счётчик. «Мои объявления» получает кнопки действий по статусу; редактирование — отдельная страница с загрузкой объявления по `GET /api/ads/{id}` (доступно автору или модератору). Карточка ленты показывает `thumbnailUrl` либо плейсхолдер.

## Risks / Trade-offs

- **Файлы и транзакция БД не едины** → файлы пишутся до сохранения записи; при сбое возможны осиротевшие файлы. Приемлемо для первой версии, очистка — отдельной задачей.
- **Проверка типа по содержимому** → ImageSharp отклоняет повреждённые и неподдерживаемые файлы; проверка `ContentType` остаётся дополнительной.
- **Локальный том не масштабируется горизонтально** → первая версия работает на одном сервере, абстракция готова к S3.
- **Автоархив раз в час** → объявление может прожить до 7 дней и часа; это допустимо и не нарушает правило «через 7 дней».
- **SkiaSharp — новая зависимость с нативными библиотеками** → выбрана MIT-библиотека; добавлены нативные ассеты для Windows и Linux.

## Migration Plan

1. Схема не меняется, миграции не создаются.
2. Каталог `media/` создаётся при первом сохранении; в репозиторий не попадает.
3. Проверка: `dotnet build`, тесты бэкенда, `pnpm test`, `pnpm build`.
4. Откат — предыдущая версия; данные совместимы.
