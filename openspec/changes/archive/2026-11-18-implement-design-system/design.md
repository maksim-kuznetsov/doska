# Design

## Context

См. `proposal.md` — Why. Сейчас:

- `frontend/src/style.css` содержит общие классы (`page`, `field`, `button`, `card`), а `HomeView`, `MyAdsView`, `AdFormView`, `AdEditView`, `AdminCategoriesView`, `ModerationQueueList`, `CategoryMenu` и `PasswordHints` добавляют собственные `scoped`-стили.
- Оболочка `DefaultLayout.vue` собрана вручную: бренд, бургер, навигация и аккаунт без компонентов.
- Шапка не содержит поиска; меню пользователя как компонента нет.
- Стили не подключены слоями и не используют токены.

## Goals / Non-Goals

**Goals:**

- Один источник оформления: токены → базовые стили → компоненты → раскладка.
- Страницы собираются из компонентов, а не из собственных классов.
- Соблюсти требования `design-system` и не сломать существующие тесты и сценарии.

**Non-Goals:**

- Тёмная тема, иконки-картинки, визуальные регрессионные тесты.
- Изменение бизнес-логики, API и схемы БД.

## Decisions

### 1. Слои CSS и токены

`tokens.css` объявляет CSS-переменные палитры, шкалы типографики, отступов, радиусов, теней, состояний и точек перелома. `base.css` задаёт сброс, фон страницы, базовую типографику и фокус. `components.css` содержит классы всех компонентов, `layout.css` — оболочку и сетки страниц. `main.ts` подключает ровно эти четыре файла; `style.css` удаляется. Значения цветов и размеров в компонентах берутся только из переменных.

Альтернатива — оставить `scoped`-стили и постепенно переводить страницы — нарушает требование «единый источник оформления» и оставляет расхождения.

### 2. Компоненты с классами дизайн-системы

Компоненты Vue не содержат `scoped`-стилей: их разметка использует классы из `components.css`. Это позволяет странице-гайду показывать те же классы и гарантирует, что представления не вводят оформление. Имена классов — BEM (`ad-card__title`, `filter-panel__row`).

### 3. Поля формы — компоненты `TextField`, `TextAreaField`, `SelectField`

Каждый компонент объединяет подпись, поле, подсказку и текст ошибки и связывает их через `id`/`for`/`aria-describedby`. `SubsectionSelect` — отдельный компонент для одного сгруппированного списка подразделов. `FormGrid` + `FormGridItem` дают две колонки и широкий элемент. `CharCounter` показывает `текущее/предел`.

### 4. Выпадающее меню с мостом наведения

`DropdownMenu` держит триггер и панель в одном контейнере; панель начинается сразу под триггером, а визуальный отступ создаётся внутренним `padding-top`. Поэтому путь указателя от кнопки к панели не пересекает «мёртвую зону». Меню открывается наведением, переключается нажатием, закрывается по `Escape`, клику вне и выбору пункта; триггер получает `aria-expanded` и `aria-controls`.

### 5. Шапка и меню пользователя

`SiteHeader` содержит бренд, `CategoryMenu` (бургер), форму поиска, `ActionLink` «Подать объявление» и `UserMenu`; для неавторизованного — ссылки «Войти» и «Регистрация». Поиск ведёт в ленту с параметром `query`. `UserMenu` группирует пункты разделителями: объявления, служебные разделы, выход.

### 6. Гайд только в Development

Маршрут `/design-system` добавляется в `router/index.ts` под условием `import.meta.env.DEV`. В `Production` маршрута нет, поэтому страница недоступна. Гайд показывает токены и примеры всех компонентов, включая фильтры, галерею, строки, модерацию, подсказки, бургер и формы.

### 7. Совместимость с существующими тестами

`CategoryMenu` сохраняет кнопку `aria-label="Категории"`, контейнер `[data-test="category-tree"]` и текст «Категорий пока нет»; `ModerationQueueList` сохраняет `[data-test="queue-item"]` и подписи кнопок; `PasswordHints` сохраняет `data-state`. Это позволяет не переписывать существующие тесты.

## Risks / Trade-offs

- **Много новых компонентов сразу** → библиотека небольшая и плоская, каждый компонент отвечает за один блок; гайд служит точкой проверки.
- **Отказ от `scoped`-стилей** → классы глобальны, возможны конфликты имён; риск снижен BEM-именованием и единым файлом компонентов.
- **Ховер-меню на сенсорных экранах** → меню также переключается нажатием, поэтому остаётся доступным.
- **Поиск в шапке дублирует фильтр ленты** → оба ведут на один маршрут с `query`; состояние остаётся в адресе.

## Migration Plan

1. Добавить токены и слои стилей, подключить их в `main.ts`, удалить `style.css`.
2. Добавить компоненты и перевести на них представления.
3. Добавить гайд и маршрут только для `Development`.
4. Проверка: `pnpm --dir frontend test`, `pnpm --dir frontend build`, бэкенд-тесты не затронуты.
5. Откат — предыдущая версия интерфейса; API и данные не меняются.
